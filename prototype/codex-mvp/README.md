# 밭보다

> 머리부터 밭끝까지, 첫 농사의 근거를 보다

농지 위치와 희망 작물, 확인 기간을 입력하면 공공데이터 여섯 곳을 **필지 단위로** 조합해 농촌진흥청 공식 생육 기준과 대조하고, 재배 판단 단계·선택 기간 위험·예방 행동을 근거와 함께 보여주는 Next.js 프로토타입이다.

2026 지역 산업 문제 기반 AI 해커톤 예선 제출작(팀 김남궁택, 문제정의서 1 기업 문제). `prototype/antigravity-mock`은 참고 원본으로 보존하며, 제출 기준 구현은 이 폴더다.

---

## 무엇을 하는가

**입력** — 지도에서 고른 지점 → 주변 농지 후보에서 지번으로 내 필지 확정 / 작물 5종(사과·배·오이·감자·상추) 중 하나 / 확인 기간 1일 또는 3일

**출력** — 재배 판단 단계(`적합` · `조건부 적합` · `현장 확인 필요`), 판단 근거 세 가지(토양 적성·토양 산도·가까운 기간 위험), 먼저 할 일 세 가지(시점 포함), 쉬운 설명, 그리고 항목별 실제 값과 공식 기준 대조표·출처·기준시각

행정구역 평균값을 쓰지 않는다. 같은 면 안에서도 필지마다 토양 등급과 산도가 다르기 때문이다.

## 판정 방식 — `v4-stage-first`

점수로 등급을 정하지 않는다. **공식 밭 적성등급과 작물별 pH 상태로 판단 단계를 먼저 정하고**, 숫자 지수는 보조로만 쓴다. 초기 임계값 방식이 파라미터 변화에 흔들려 폐기한 결과다(아래 검증 참조).

- 밭 적성등급은 물리적 제한을 이미 종합하므로 배수를 적합 지수에 중복 감점하지 않고 선택 기간 위험에만 반영한다.
- 공식 범위 이탈 거리는 연속 감점하고, 작물별 정성적 민감도는 `1.00 · 1.15 · 1.30`의 운영 계수로만 변환한다. 이 계수는 현장 라벨로 보정된 농업 계수가 아니다.
- 핵심 값인 pH 또는 밭 적성등급이 없으면 숫자로 낙관하지 않고 `현장 확인 필요`로 판정한다.
- 허용범위 밖 입력은 점수에서 제외하고 근거 상태에 기록한다.

V3 코드 해석과 단계 판정 근거는 [`docs/20260724_토양특성_V3_공식_코드표와_v4_판정.md`](../../docs/20260724_토양특성_V3_공식_코드표와_v4_판정.md)에 있다.

## AI 역할과 검사

**판정은 규칙이, 설명은 AI가 한다.** AI는 판정이나 수치를 바꿀 수 없다.

1. 규칙 엔진이 판정과 수치를 확정한다.
2. 확정된 **근거 묶음만** 프롬프트로 넘긴다.
3. 생성된 문장을 다섯 가지로 검사한다 — 판정을 그대로 인용했는지 / 금지 표현이 없는지 / 근거에 없는 숫자를 만들지 않았는지 / 정해진 구성을 지켰는지 / 길이가 적절한지.
4. 하나라도 걸리면 화면에 내보내지 않고 **같은 근거로 만든 규칙 문장으로 되돌린다.** 걸린 이유도 화면에 표시한다.

생성 과정 5단계와 검사 결과는 `03 자세한 근거` 화면에 그대로 노출된다. 강조 색도 규칙이 고른다(실측값·공식 기준·주의 표현). AI가 어디를 강조할지 정하지 않는다.

### `LLM_PROVIDER` 전환

| 값 | 동작 | 화면 배지 |
|---|---|---|
| `none` | 규칙 문장만 사용 (기본값) | — |
| `gemini` | Gemini 실시간 호출 | `AI 설명 · Gemini 2.5 Flash · 검사 통과` |
| `replay` | 저장해 둔 **실호출 응답** 재생. 사람이 쓴 문장은 넣지 않는다 | `AI 설명 · Gemini 2.5 Flash · 7월 26일 작성 · 검사 통과` |
| `replay-live` | 저장본이 있으면 재생하고 **없으면 실시간 호출**. 배포 기본값 | 저장본 재생 시 위와 같고, 실시간이면 `… · 실시간 생성 · 검사 통과` |
| `curated` | 사람이 쓴 예시 문안. AI 아님을 화면에 명시 | `규칙이 조립한 안내문 · AI 생성 아님` |
| `tampered` | 규칙 위반 문장 주입. 검사가 막는지 확인하는 시연용 | `AI 문장이 검사에 걸려 규칙 문장을 표시` |
| `anthropic` | Claude 실시간 호출 | 동일 계약 |

`replay`는 시연 중 무료 한도·네트워크에 의존하지 않기 위한 설정이다. 저장된 응답은 [`lib/report/snapshots/llmResponses.json`](lib/report/snapshots/llmResponses.json)에 있고 **실제 호출 결과만** 넣는다. 재생본도 매번 같은 검사를 통과해야 화면에 나간다.

배포에는 `replay-live`를 쓴다. `replay`만 쓰면 저장해 둔 조합 밖에서는 AI 문장이 나오지 않고, `gemini`만 쓰면 무료 한도가 소진되는 순간 모든 조합이 규칙 문장으로 내려간다. 둘을 합쳐 **시연 조합은 저장본으로 고정하고 나머지는 실시간으로** 답한다. 한도 초과나 호출 실패는 그대로 규칙 문장으로 내려가고 실패 사유를 `03 자세한 근거` 화면에 적는다.

호출량은 분석 1회당 2건이다. `02 판정서`의 쉬운 설명과 `04 쉬운 말 보고서`가 각각 한 번 부른다. 시연할 조합을 미리 저장해 두면 그만큼 호출이 줄어든다.

### 고친 것과 확인한 수치

| 발견한 문제 | 조치 | 확인한 결과 |
|---|---|---|
| 점수 임계값 방식이 파라미터에 흔들렸다 | 점수로 등급을 정하는 방식을 폐기하고 공식 등급·pH 상태로 단계를 직접 결정 | 560개 합성 시나리오에서 감점 폭 ±20% 조정 시 **적합도 단계 변동 0%** |
| 주 판정 근거가 비어 있었다 | 토양검정이 `요청 데이터 없음`일 때 정상 응답한 토양특성까지 함께 버리던 코드 수정 | 표본 24필지 조회 성공 **0/24 → 24/24** |
| 다른 필지의 토양값이 붙을 수 있었다 | 캐시 좌표 허용 오차를 좁히고, 사용자가 필지를 확정했으면 PNU 일치를 요구 | 허용 오차 **0.02°(약 2km) → 0.002°** |
| 지도가 결과 화면에서 사라지지 않았다 | 숨기는 대신 렌더하지 않도록 변경 | 겹쳐 보이던 높이 **2,385px → 0** |

**같은 감사에서 위험 등급은 흔들린다.** ±20% 조정 시 위험 라벨 변동은 완화 방향 60.0%, 보수 방향 10.0%였다. 위험은 그날 예보에 직접 반응하도록 설계했기 때문이고, 감사 테스트도 이 변동이 0이 아님을 명시적으로 확인한다. 안정성을 주장하는 것은 **주 판정 단계뿐**이다.

실시간 확인 기록: 평창 대관령 좌표에서 팜맵 후보 356건 중 `대관령면 85-61전` 확정, PNU 토양특성 V3 1건, 최근 7일 농업기상 7건, 최근접 관측소 `강릉 안반덕이` 6.45km, 연결 소스 4/4.

## 실행

Node.js `20.9.0` 이상이 필요하다.

```powershell
npm ci
npm run dev
```

`http://localhost:3000`을 연다. 프로젝트 루트의 `밭보다_MVP_실행.bat`은 Node 버전과 패키지를 확인한 뒤 개발 서버와 브라우저를 순서대로 연다.

### 환경변수

`.env.local`은 저장소·문서·채팅에 공유하지 않는다. 템플릿은 [`config/api.env.example`](../../config/api.env.example)에 있다.

```dotenv
PUBLIC_DATA_MODE=mock
DATA_GO_KR_SERVICE_KEY=발급받은_일반_인증키_Decoding
LLM_PROVIDER=none
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.5-flash
```

- 키는 서버에서만 쓴다. 클라이언트에는 키 값이 아니라 **설정 여부만** 전달한다.
- 화면의 `실제 공공데이터로 조회`를 켜면 실제 API를 호출한다. 순서는 `지도 핀 → 반경 1km 팜맵 후보 → 지번 검색·필지 확정 → PNU 토양 조회 → 단기예보·최근 농업기상`이다.
- 모델 선택은 **사고 과정을 끌 수 있는지**로 갈린다. `gemini-3.5-flash`는 `thinkingBudget: 0`이 먹혀 한 번에 1.4초로 끝나지만, `gemini-3.6-flash`와 별칭 `gemini-flash-latest`는 이 값을 거부해 사고 토큰이 항상 붙고 4.6초가 걸린다(2026-08-04 실측). 분석 1회가 호출 2건이라 이 차이가 그대로 화면 대기 시간이 된다.
- `gemini-2.5-flash`는 2026-08-04부터 **신규 프로젝트에서 404로 거부된다**. 유료 전환하며 프로젝트를 새로 만들면 쓸 수 없다.

## 재현

키가 없어도 흐름 전체를 확인할 수 있다. 두 겹의 스냅샷이 모두 `대관령면 85-61전 + 상추 + 3일` 조합에 맞춰져 있다.

| 스냅샷 | 파일 | 내용 |
|---|---|---|
| 공공데이터 | [`lib/cache/snapshots/verified.json`](lib/cache/snapshots/verified.json) | 2026-07-26 13:44 수집. pH 6.9, 검정 시점 2025-05-02, 관측소 안반덕이 |
| LLM | [`lib/report/snapshots/llmResponses.json`](lib/report/snapshots/llmResponses.json) | 실제 Gemini 2.5 Flash 응답 2건 (02 판정서용·04 보고서용) |

각 스냅샷에는 출처·수집시각·재현 절차가 함께 들어 있다. 실시간 호출이 실패하면 실패한 소스만 스냅샷으로 대체하고, 성공한 실데이터와 소스별 상태·실패 이유는 그대로 유지한다. **캐시는 실시간 연결로 세지 않고 화면에 따로 표시한다.**

스냅샷을 갱신할 때는 개발 서버에서 아래를 호출한다. 운영 빌드에서는 동작하지 않는다.

```
/api/cache/capture?lat=..&lng=..&parcelId=..&horizonDays=..   # 공공데이터
/api/report/capture?...                                        # LLM 응답 (02·04 동시)
```

요청 PNU가 팜맵 후보에 없으면 저장하지 않는다.

## 한계

소개서와 화면에 같은 내용을 적어 두었다. 숨기지 않는 것이 이 서비스의 설계 원칙이다.

- **토양검정 이력이 있는 필지가 적다.** 대관령 반경 1km 258필지 중 pH가 나오는 필지는 18건(7.0%)이었다. 이 경우 pH 없이 판정하고 신뢰 표시를 낮춘다.
- **최근 7일 관측을 판정 점수에 넣지 않는다.** 화면에 보여주되 상황 참고용이라고 함께 적는다. 최근접 관측소가 농지의 미기후를 그대로 대표한다고 단정하지 않는다.
- **확인 기간이 3일이다.** 단기예보 범위다. 중기예보는 연결하지 않았다.
- **관측소가 농지와 떨어져 있다.** 예: 6.45km. 공간 대표성 한계로 남기고 관측소 이름과 거리를 함께 표시한다.
- **작물 5종이다.** 공식 기준 장부를 확보한 작물만 추가한다.
- 감자 역병 환경 신호는 공식 길잡이의 저온·다습·잦은 비 설명을 조합한 것으로, 공식 예측모형이나 발병 확률이 아니며 위험 점수에 중복 가산하지 않는다.
- EC는 API 명세에 단위가 없어 농촌진흥청 흙토람 공식 화면과 교차해 `dS/m`로 표시하되, 작물·작형별 기준이 확정되기 전까지 점수에서 제외한다.
- 토양 경계는 존재 여부만 확인하며 GML 폴리곤을 지도에 표시하지 않는다.
- 지도 타일은 OpenStreetMap 네트워크가 필요하다. 실패 시에도 대표 지역 버튼으로 분석할 수 있다.
- **정확도는 검증되지 않았다.** 현장 라벨과 대조한 예측 성능 평가를 하지 않았다. 이 서비스는 재배 판단을 돕는 참고 도구이며, 실제 영농 결정 전 현장 확인과 전문가 검토가 필요하다.
