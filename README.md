# 밭보다

> 머리부터 밭끝까지, 첫 농사의 근거를 보다

농지 위치와 희망 작물, 확인 기간을 입력하면 공공데이터 여섯 곳을 **필지 단위로** 조합해 농촌진흥청 공식 생육 기준과 대조하고, 재배 판단 단계·선택 기간 위험·예방 행동을 근거와 함께 보여주는 서비스입니다.

**2026 지역 산업 문제 기반 AI 해커톤 · 장려상.** 팀 김남궁택(남궁도현·김택명), 문제정의서 1 기업 문제.

**배포 → <https://batboda.vercel.app>**

---

## 왜 만들었나

귀농 준비자는 "이 땅에 이 작물이 맞는가"를 판단할 근거를 스스로 모으기 어렵습니다. 토양 정보와 기상 정보가 서로 다른 기관에 흩어져 있고, 대부분의 정보 서비스는 시·군 단위 평균값을 보여줍니다. **같은 면 안에서도 필지마다 토양 등급과 산도가 다르기 때문에, 평균값으로는 "내 땅"의 판단이 되지 않습니다.**

그래서 지도에서 고른 지점을 팜맵으로 필지까지 좁히고, 그 필지의 고유번호로 토양 자료를 조회해 작물별 공식 생육 기준과 대조합니다. 판단의 근거가 된 값과 그 값의 출처·기준시각을 함께 보여주어, 사용자가 결론만이 아니라 근거까지 확인할 수 있게 했습니다.

확인되지 않은 값을 그럴듯하게 채우지 않습니다. 자료가 없으면 없다고 표시하고, 판단에서 낙관하지 않습니다.

---

## 설계에서 지킨 두 가지

**판정은 규칙이, 설명은 AI가 합니다.** 규칙 엔진이 공식 기준으로 판정과 수치를 확정한 뒤, 확정된 근거만 생성형 AI에 넘겨 초보자의 말로 옮기게 합니다. AI는 판정을 바꿀 수 없습니다.

AI가 쓴 문장은 다섯 가지 검사를 통과해야 화면에 나갑니다 — **판정·위험 등급을 그대로 인용했는지 / 금지 표현이 없는지 / 근거에 없는 숫자를 만들지 않았는지 / 정해진 구성을 지켰는지 / 길이가 적절한지.** 하나라도 걸리면 같은 근거로 만든 규칙 문장으로 되돌리고, **걸린 이유와 어느 단계에서 멈췄는지를 화면에 적습니다.**

외부 API에 의존하는 계층이므로 실패를 전제로 만들었습니다. 시연 조합은 실제 호출로 받은 응답을 저장해 두고 재생하므로 한도·네트워크와 무관하게 같은 문장이 나오고, 그 밖의 농지는 실시간으로 답합니다. 저장본도 매번 같은 검사를 거치며, **판정이 저장 시점과 달라지면 쓰지 않습니다** — 화면 판정과 설명이 다른 결론을 말하면 안 되기 때문입니다. 주 모델이 응답하지 않으면 예비 모델로 이어 부릅니다.

**근거를 숨기지 않습니다.** 어떤 API의 어떤 값을 썼는지, 기준시각이 언제이고 그 나이가 이 자료에서 문제인지 아닌지까지 화면에 공개합니다. 한계도 같은 화면에 적습니다. AI 호출이 실패하거나 검사에 걸린 경우에도 **무엇이 어디서 멈췄는지** 화면에 그대로 적습니다.

## 무엇을 보여주는가

네 쪽으로 나눠 한 화면에 담기는 정보량을 고정했습니다.

| 쪽 | 내용 |
|---|---|
| **01 농지·작물·기간** | 지도에서 지점 선택 → 주변 농지 후보에서 지번으로 필지 확정. 확정한 필지는 경계를 지도에 그립니다. 내 농지 즐겨찾기 |
| **02 농지 환경 판정서** | 재배 판단 단계(`적합`·`조건부 적합`·`현장 확인 필요`), 판단 근거 세 가지와 기준 대비 눈금, 먼저 할 일, 쉬운 설명 |
| **03 자세한 근거** | 항목별 실측값과 공식 기준 대조, 예보, 농지 확인표, 최근 관측, 판정 방식, 계산 과정, **사용한 자료와 기준시각·자료 나이** |
| **04 쉬운 말 보고서** | 초보자 눈높이 자연어 설명. 실측값·공식 기준·주의 표현을 색으로 구분하며, **강조 위치는 규칙이 고릅니다** |

02와 04는 인쇄해 상담 창구에서 종이로 건넬 수 있습니다.

## 빠른 시작

Node.js `20.9.0` 이상이 필요합니다. 공공데이터 인증키가 없어도 저장된 검증 스냅샷으로 전체 흐름을 확인할 수 있습니다.

```bash
cd prototype/codex-mvp
npm ci
npm run dev
```

`http://localhost:3000`을 엽니다.

```bash
npm run test    # 13개 파일 115개 테스트
npm run lint
npm run build
```

인증키를 넣어 실제로 조회하려면 [`config/api.env.example`](config/api.env.example)을 `prototype/codex-mvp/.env.local`로 복사해 값을 채웁니다. 키는 서버에서만 읽고 클라이언트로 내려보내지 않습니다.

## 확인한 수치

| 발견한 문제 | 조치 | 확인한 결과 |
|---|---|---|
| 점수 임계값 방식이 파라미터에 흔들렸다 | 공식 등급·pH 상태로 판단 단계를 직접 결정 | 560개 시나리오에서 감점 폭 ±20% 조정 시 적합도 단계 변동 **0%** |
| 주 판정 근거가 비어 있었다 | 토양검정 실패 시 정상 응답한 토양특성까지 버리던 코드 수정 | 표본 24필지 조회 성공 **0/24 → 24/24** |
| 다른 필지의 토양값이 붙을 수 있었다 | 캐시 좌표 허용 오차를 좁히고 PNU 일치를 요구 | 허용 오차 **0.02°(약 2km) → 0.002°** |

같은 감사에서 **위험 등급은 흔들립니다.** ±20% 조정 시 위험 라벨 변동은 완화 방향 60.0%, 보수 방향 10.0%였습니다. 위험은 그날 예보에 직접 반응하도록 설계했기 때문이고, 안정성을 주장하는 것은 주 판정 단계뿐입니다.

실시간 조회는 대관령 외에도 확인했습니다 — 경기 이천 468건, 경북 영주 430건, 김제 753건, 나주 280건이 모두 실시간으로 응답했습니다. 특정 지역 전용이 아닙니다.

## 한계

**현장 정확도는 검증하지 않았습니다.** 현장 라벨과 대조한 예측 성능 평가를 하지 않았습니다. 위에 적은 560개 시나리오 감사는 자체 설계한 가중치의 민감도와 코드 회귀까지이고, 현장 정확도가 아닙니다.

토양검정 이력이 있는 필지가 적고(대관령 반경 1km 258필지 중 pH 확인 18건, 7.0%), 확인 기간은 단기예보 범위인 3일까지이며, 최근 관측은 농지에서 떨어진 관측소 기록입니다. **산도가 조회되지 않는 필지에서는 값을 추정해 채우지 않고, 없다고 표시한 뒤 밭 적성등급으로 판정합니다.**

**재배 판단을 돕는 참고 도구입니다. 실제 영농 결정 전 현장 확인과 전문가 검토가 필요합니다.**

전체 한계 목록은 [`prototype/codex-mvp/README.md`](prototype/codex-mvp/README.md#한계)에 있습니다.
