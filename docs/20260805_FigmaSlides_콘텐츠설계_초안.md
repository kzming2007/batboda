## 1. 발표의 한 문장 목표

발표가 끝났을 때 평가위원은 밭보다를 다음 문장으로 기억해야 한다.

> **밭보다는 사용자가 경계를 확인한 필지의 PNU 토양과 그 좌표의 단기예보를 작물별 공식 기준에 대조하고, 출처·시각·결측까지 공개하는 참고 판정 도구다.**

첫 발표팀이므로 `토양·날씨 서비스`라는 넓은 범주가 아니라 다음 다섯 고리를 이후 팀을 보는 비교 기준으로 먼저 심는다.

> **필지 경계 확인 → 같은 PNU 토양 → 작물별 공식 등급 → 좌표 예보 → 근거 추적**

다른 팀의 기능 부재나 우열은 말하지 않는다. 밭보다가 무대에서 직접 보여 줄 수 있는 연결만 주장한다.

## 2. 콘텐츠 편집 원칙

- 한 장에는 주장 하나만 둔다. 제목만 읽어도 전체 논리가 이어져야 한다.
- 관객용 문구에는 작업 지시, 시간표, 내부 검토 용어, `[사실]/[제안]/[미확인]` 표기를 노출하지 않는다.
- 실제 제품 화면을 주 시각자료로 쓴다. 예선 소개서의 오래된 UI 캡처는 재사용하지 않는다.
- 보이지 않는 기능을 설명으로 메우지 않는다. 현재 화면에서 증명되거나 문서로 확인된 내용만 본문에 둔다.
- `정확한 추천`, `수확량 예측`, `피해 예방`, `기관 도입`, `운영비 0원`, `유일한 서비스`를 주장하지 않는다.
- 운영·수익 모델은 `현재 운영 사실`이 아니라 `검증할 실증 가설`로 표현한다.
- 숫자는 이 문서 5절의 허용 목록만 사용하고, 날씨처럼 변하는 값에는 실측 날짜를 붙인다.
- 출처는 화면을 어지럽히지 않도록 발표자 노트의 `[Sources]` 블록에 둔다.
