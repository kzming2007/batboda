## 1. 감사 기준

1. 초보 귀농인이 화면에서 하는 질문에 그 자리에서 답하는 한국어를 쓴다.
2. 영어 장식 라벨, 내부 개발 용어(`Mock`, `P0`, `v4-stage-first`, `정합`, `대시보드`)를 사용자 화면에서 없앤다.
3. 공식 데이터명·코드값(`PNU`, `밭 적성등급`, `표토토성`)은 숨기지 않고 괄호로 쉬운 설명을 병기한다.
4. 주체와 근거가 모호한 확신 표현을 쓰지 않는다.
5. 1분 영상에 실제로 잡히는 문구를 우선 고친다.

## 6. 판단이 필요한 항목

**요구사항 충족 블록**(`FarmDecisionApp.tsx:560-584`, 상태값 `연결 / 부분 / 결정 필요`)

이 블록은 공식 요구사항 9개를 어디까지 연결했는지 보여준다. 심사위원에게는 유리하지만 사용자 화면 문구로는 `결정 필요`가 무엇을 뜻하는지 알 수 없다. 두 갈래 중 선택이 필요하다.

1. 이름만 `사용한 자료와 현재 범위`로 바꾸고 상태값을 `연결됨 / 일부만 / 아직 없음`으로 고친다. 심사 근거를 유지하면서 사용자 화면 어휘를 맞춘다. (권장)
2. 결과 화면 하단으로 내리고 사용자 결론 영역에서 분리한다.

**`토양 판단 보조 지수` / `선택 N일 위험 지수`**(`FarmDecisionApp.tsx:594,605`)

`지수`가 두 카드에 반복되고, 단계 판정과 시각 비중이 비슷하다. 2026-07-24 결정은 숫자를 보조로 낮추는 것이므로 문구뿐 아니라 크기·위치도 함께 조정해야 한다. 문구는 `토양 조건 점수(보조)`, `가까운 {N}일 위험 점수(보조)`를 제안한다.

## 7. 감사에서 문제가 없다고 본 문구

- `현장 확인 필요 / 조건부 적합 / 적합` — 단계 판정 어휘가 명확하다.
- `아래 지수는 규칙 기반 비교값이며 성공 확률이나 수확량 예측이 아닙니다.` — 과장 방지 문구로 유지.
- `가장 가까운 관측소라는 사실만으로 농지와 같은 미기후라고 단정하지 않으며…` — 한계 표시가 정확하다.
- 예방 행동 4종(`배수로와 고랑을 먼저 점검` 등)과 시점 표기 — 행동 지향적이고 초보자가 실행 가능하다.
- `근거를 모으는 중…` — 진행 상태 표현으로 적절하다.
- `AI가 분석했습니다` 같은 모호한 주체 표현은 현재 코드에 없다.

## 8. 적용 순서 제안

1. 2절 P0 13건을 먼저 적용한다. 영상에 잡히는 문구와 오해 위험이 여기 모여 있다.
2. 3~4절 P1을 적용한다.
3. 6절 두 항목은 팀 확인 후 문구와 시각 비중을 함께 조정한다.
4. 적용 후 `npm run test`·`npm run build`를 다시 통과시키고, 문구가 테스트 단정문에 쓰인 곳이 있으면 함께 수정한다.
