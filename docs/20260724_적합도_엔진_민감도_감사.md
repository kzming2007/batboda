# 적합도 엔진 v3.1 민감도 감사

> 작성일: 2026-07-24  
> 대상: `prototype/codex-mvp`의 규칙 기반 적합도·위험 엔진  
> 상태: v3.1의 문제를 확인한 역사적 감사. 현재 구현은 `v4-stage-first`이며 `20260724_토양특성_V3_공식_코드표와_v4_판정.md`를 따른다.  
> 결론: **가중치·감점 폭·등급 경계의 확정은 단순 UI 조정이 아니라 제출 신뢰도를 좌우하는 중대사항이다.**

## 1. 현재 구현에서 확정된 것과 확정되지 않은 것

### 공식 근거를 사용한 부분

- 다섯 작물의 pH·기온 적정 범위
- 작물별 배수·과습·고온 등의 정성적 주의점
- 허용범위 밖 값, 결측값을 그대로 정상값처럼 계산하지 않는 원칙
- 병해 신호를 발병 확률이나 수확량 예측으로 표현하지 않는 원칙

### 아직 운영 가정인 부분

- pH·기온 이탈의 최대 감점 폭
- 배수 상태별 감점
- `1.00 / 1.15 / 1.30` 민감도 배율
- 강수확률 `60%`, 습도 `85%` 운영 임계값
- 적합·조건부 적합·현장 확인 필요의 점수 경계
- 낮음·주의·높음의 위험 점수 경계

따라서 현재 `v3.1-baseline`은 설명 가능한 **비교 기준선**이지, 현장 정확도가 검증된 농업 모델이 아니다. 이 구분을 코드의 `modelPolicy.ts`와 화면의 `MODEL STATUS`에 명시했다.

이 결과를 반영해 v4에서는 `적합 / 조건부 적합 / 현장 확인 필요` 주판정을 숫자 임계값에서 분리했다. 공식 밭 적성등급과 작물별 pH 상태가 단계를 정하고, 숫자는 비교용 보조 지수로만 남긴다.

## 2. 이번 구현 보강

1. 운영 파라미터를 `lib/analysis/modelPolicy.ts`로 분리하고 버전을 부여했다.
2. 토양 API의 공식 `ecd` 필드를 파싱하도록 추가했다.
3. 공식 API 명세에는 EC 단위가 없지만 흙토람 공식 화면과 교차해 `dS/m`로 표시한다. 작물·작형별 판정 기준이 없으므로 점수에는 반영하지 않는다.
4. 화면에 `실제 토양 / 최근 기후 추이 / 단기예보 / 초보자 설명`의 요구사항 충족 상태를 표시한다.
5. 최근 기후와 실제 LLM이 미연결인 사실을 결과 화면에서 숨기지 않는다.
6. pH 이탈 단조성과 운영 파라미터 민감도를 자동 테스트에 추가했다.

## 3. 민감도 실험

### 방법

- 작물 5종
- pH 7단계: `4.5, 5.0, 5.5, 6.0, 6.5, 7.0, 7.5`
- 배수 4단계: `양호, 보통, 불량, 자료 없음`
- 기상 4상황: 저온·건조, 적온·건조, 적온·다습, 고온·다습
- 총 `560`개 합성 시나리오
- 현재 감점·기여도 폭을 기준으로 `-20%`와 `+20%` 정책을 비교
- 등급 경계와 공식 적정 범위는 고정

### 결과

| 비교 정책 | 적합도 등급 변경률 | 위험 등급 변경률 |
|---|---:|---:|
| 감점 폭 -20% | 16.4% | 40.0% |
| 감점 폭 +20% | 20.0% | 12.5% |

pH가 공식 범위에서 멀어질수록 적합 지수가 역으로 오르지 않는 단조성 검사는 다섯 작물 모두 통과했다.

### v4 재실험

동일한 560개 합성 시나리오에서 운영 감점 폭을 ±20% 조정했을 때 주판정 단계 변동률은 양쪽 모두 `0%`였다. 반면 선택 기간 위험 등급은 감점 완화 시 `60%`, 보수화 시 `10%` 변동했다. 주판정 분리는 완료됐지만 단기 위험 기여도·경계의 보정은 여전히 남아 있다.

### 해석 한계

- 이 실험은 모델의 **파라미터 민감도**를 측정한 것이며 농업적 정확도를 측정한 것이 아니다.
- 합성 시나리오는 경계조건을 넓게 포함하므로 실제 사용자 분포와 같지 않다.
- 그럼에도 ±20% 조정만으로 최대 40%의 등급이 바뀐다는 결과는 현재 결론이 운영 파라미터에 민감함을 보여준다.

## 4. 객관적 중요도 판정

**P0 중대사항**으로 분류한다.

이유는 다음과 같다.

1. 문제정의서가 변수별 가중치, 이탈 정도, 작물별 민감도, 시계열·예보, 결측·이상치 처리를 핵심 요구사항으로 직접 요구한다.
2. 사용자가 가장 먼저 보는 `적합 / 조건부 적합 / 현장 확인 필요`가 이 파라미터에 따라 바뀐다.
3. 현재 실험에서 파라미터 변화에 따른 등급 전환이 적지 않았다.
4. EC·토성·배수·최근 기후가 비어 있는 상태에서 숫자를 더 정교하게 조절해도 실제 타당도가 자동으로 높아지지 않는다.

따라서 제출 전에는 최소한 `공식 근거`, `운영 가정`, `미연결 변수`, `민감도 결과`를 한 장에서 설명하고, 대표 시연·경계 사례에서 사람이 결론을 검토해야 한다. 현장 정확도 검증까지 예선 기간에 끝내는 것은 현실적이지 않으므로 `검증용 의사결정 보조 지수`라는 범위를 유지한다.

## 5. 다음 보정 절차

1. **정답 정의:** 전문가 적합 등급, 실제 재배 성과, 또는 공식 토양적성 등 무엇을 검증 기준으로 삼을지 정한다.
2. **변수 근거표:** 작물·작형·생육 단계별로 변수, 단위, 적정 범위, 한계, 출처를 고정한다.
3. **데이터 완성:** 토성·배수·유효토심, 최근 기후 관측을 연결하고 EC의 작물·작형별 판정 기준을 검증한다.
4. **전문가 검토:** 농업기술센터·공식 지침 등으로 가중 방향과 등급 경계를 확인한다.
5. **민감도·경계 실험:** 가중치와 임계값을 ±10~20% 변화시키고 결론 전환이 잦은 구간을 표시한다.
6. **대표 사례 검증:** 적합 사례, 조건부 사례, 결측 사례, 이상치 사례를 작물별로 최소 한 번씩 확인한다.

## 6. 팀 논의가 필요한 결정

- 최근 기후 추이에 농촌진흥청 `농업기상 기본 관측데이터 조회`를 추가 신청할지
- 선택 필지와 최근접 관측소를 어떤 거리·고도 기준으로 연결할지
- 최종 결과를 하나의 종합점수로 유지할지, 토양 적합·최근 추이·예보 위험의 단계 판정으로 분리할지
- EC의 작물·작형별 판정 기준을 어떤 공식 자료로 제한할지
- LLM 제공자·API 비용·키·실패 시 템플릿 대체 방식을 어떻게 정할지
- 노지·시설과 생육 단계를 P0 입력에 포함할지, 대표 시연 조건으로 고정할지
