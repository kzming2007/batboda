## 1. 결론

현재 키 하나로 예선 MVP의 핵심 흐름을 구현할 수 있다. 다만 기존 구현처럼 `팜맵 첫 응답 = 선택 필지`로 간주하면 서로 다른 필지의 농지 정보와 토양검정값을 합칠 위험이 있다. 실제 감사에서도 팜맵 첫 후보와 좌표 기반 토양 응답의 마스킹 PNU가 서로 달랐다.

따라서 파이프라인의 기준을 다음처럼 바꾼다.

1. 좌표 주변 팜맵 결과는 **단일 필지가 아니라 후보 목록**으로 보존한다.
2. 좌표 기반 토양 응답이 반환한 PNU·팜맵 ID·경계를 팜맵 후보와 대조한다.
3. 일치 후보가 있으면 그 필지를 분석 기준으로 사용한다.
4. 일치하지 않거나 토양 응답이 없으면 임의의 첫 후보를 확정하지 않고 사용자가 필지를 확인하게 한다.
5. 세 API는 독립적으로 호출한다. 한 소스가 실패해도 성공한 실데이터는 유지하고 실패한 소스만 명시적으로 대체한다.
6. 단위·정의가 확인되지 않은 변수는 저장은 하되 점수와 사용자 조언에 사용하지 않는다.

### 대표 응답의 안전한 요약

- 팜맵: 대관령면, 밭, 2019년 판독 자료, 후보 30개
- 토양검정: 2025-07-01 검정, pH `7.0`, 유기물 `18 g/kg`, 시료 유형 `시설`
- 기상청: 격자 `90, 130`, 2026-07-23 14:00 발표본, 2026-07-23~27 자료 반환
- PNU 대조: 팜맵 첫 후보 `51760380…0111`, 토양 응답 `51760380…0015`로 불일치

`시설` 시료라는 실제 응답은 같은 작물이라도 노지·시설을 구분해야 한다는 근거다. MVP에서 이를 숨기지 않고 출처 정보로 표시하되, 재배 방식 선택 UX는 핵심 흐름이 안정된 뒤 결정한다.

## 3. 감사에서 발견한 문제와 조치

## 4. 수정 파이프라인 v2

```text
위도·경도 + 작물 + 1/3일
  ├─ 좌표 변환: 팜맵 EPSG:5179
  ├─ 격자 변환: 기상청 nx/ny
  └─ 독립 병렬 호출
      ├─ 팜맵 후보 목록
      ├─ 좌표 기반 토양검정(PNU·경계 포함)
      └─ 기상청 단기예보
          ↓
소스별 성공·실패·기준시각 기록
          ↓
필지 정합
  ├─ 토양 PNU와 팜맵 후보 일치 → 분석 필지 확정
  └─ 불일치·결측 → 후보 미확정 표시 + 사용자 확인
          ↓
정규화된 Evidence Bundle
  ├─ 필지: 식별자·주소·농지 유형·후보 수·정합 상태
  ├─ 토양: pH·유기물·검정시점·시료 유형·출처
  └─ 날씨: 기간별 기온·강수·습도·풍속·발표시각
          ↓
사용 가능성 게이트
  ├─ 단위·정의·출처가 확인된 변수만 규칙 계산
  └─ 결측·대체 소스에 따라 확신도 하향
          ↓
규칙 기반 적합도·선택 기간 위험도 → 근거·행동 UI
```

## 5. 지도 장애 판단과 대응

같은 PC에서 OpenStreetMap의 표준 호스트와 `a` 서브도메인 타일을 직접 확인한 결과 모두 `HTTP 200 image/png`였다. 따라서 현재 보고된 지도 미표시는 서비스 전체 장애보다 브라우저 번들 로딩, 동적 import, 타일 이벤트 또는 화면 상태 처리 문제일 가능성이 높다.

P0 대응은 다음과 같다.

- 표준 타일 URL `https://tile.openstreetmap.org/{z}/{x}/{y}.png` 사용
- 지도 모듈과 타일의 로딩·실패 상태를 별도로 표시
- 타일이 실패해도 대표 지역 버튼과 현재 좌표로 분석 가능
- 지도 실패가 API 분석을 막지 않도록 입력과 분석 경로 분리
