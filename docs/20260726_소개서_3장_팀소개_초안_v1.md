# 서비스 소개서 3장(팀 소개) 개선안

> 작성일: 2026-07-26
> 대상: 공식 양식 3장. 표 1개 + 자유 서술 박스 1개 + 사진 박스로 구성돼 있다.
> 팀이 제시한 초안을 다듬은 것이며, 역할 분담 자체는 팀 결정을 그대로 따랐다.

---

## 1. 원안에서 고칠 점

| # | 문제 | 이유 |
|---|---|---|
| 1 | **`기타사항`이 비어 있다** | 양식이 요구한 칸이다. 두 칸이 모두 비면 성의 없어 보인다 |
| 2 | **담당업무가 명사 나열이다** | `공공데이터 연동`만 보면 무엇을 어디까지 했는지 알 수 없다. 심사는 기여 범위를 본다 |
| 3 | **`문서/검증 총괄`의 `총괄`이 과하다** | 2인 팀에서 총괄은 어색하다. 관리 계층이 없다 |
| 4 | **업무 개수가 4 대 3으로 불균형하다** | 기여가 한쪽에 몰린 것으로 읽힐 수 있다 |
| 5 | **`/` 슬래시 표기** | 문서 규칙상 정돈된 문체를 쓴다 |
| 6 | **두 사람이 모두 인공지능학과라는 사실이 빠졌다** | AI 해커톤에서 팀 구성 자체가 근거가 되는 정보다 |
| 7 | **자유 서술 박스가 비어 있다** | 양식이 `참여한 계기 등`을 요구한다 |

## 2. 개선안 — 표

**세 항목씩 균형을 맞추고, 각 항목을 `무엇을 했는가` 수준까지 적었다.**

| 성함 | 담당 역할 | 담당업무 | 기타사항 |
|---|---|---|---|
| 남궁도현 | 팀장 | · 문제 정의와 도메인 조사 — 문제정의서 원문 분석, 5개 작물 공식 생육 기준 장부 확보<br>· 공공데이터 활용신청 — 팜맵·토양 2종·기상 2종 승인 및 인증키 관리<br>· 판정 화면 설계 — 단계 우선 판정 구조와 결과 화면 구성 확정 | 인공지능학과<br>공공데이터 활용신청 경험 보유 |
| 김택명 | 팀원 | · 공공데이터 연동 — 5개 API 독립 호출과 소스별 실패 대체 처리<br>· 판정 엔진 구현 — 공식 기준 대조 규칙, 토양도 코드 해석, 작물별 민감도 반영<br>· 검증 — 자동 테스트 41개, 실시간 연결 4/4 확인, 민감도 감사 | 인공지능학과<br>실시간 API 검증과 기록 담당 |

### 표기 원칙

- 두 사람 모두 **세 줄**로 맞췄다. 줄 수가 다르면 기여 차이로 읽힌다
- 각 줄은 `영역 — 구체적으로 한 일` 형식이다
- 수치는 검증된 값만 적었다. 자동 테스트 41개, 실시간 연결 4/4는 실측이다
- `총괄`, `전반`, `주도` 같은 위계 표현을 쓰지 않았다

### 더 줄이고 싶다면 (한 줄 버전)

슬라이드 공간이 부족하면 이렇게 줄인다.

| 성함 | 담당 역할 | 담당업무 | 기타사항 |
|---|---|---|---|
| 남궁도현 | 팀장 | 문제 정의, 공공데이터 활용신청, 판정 화면 설계 | 인공지능학과 · 공공데이터 활용신청 경험 |
| 김택명 | 팀원 | 공공데이터 연동, 판정 엔진 구현, 검증과 테스트 | 인공지능학과 · 실시간 API 검증 담당 |

## 3. 개선안 — 자유 서술 박스

양식이 `팀 소개 / 팀원 소개 / 본 프로그램에 참여한 계기 등`을 요구한다. 4문장으로 줄였다.

> **인공지능학과 2인으로 팀을 구성했습니다.**
>
> 문제정의서의 사례는 이미 귀농한 초보 농업인이 지역 토양과 봄철 야간 저온을 놓쳐 초기 뿌리 활착에 실패한 경우였습니다. 필요한 자료는 이미 공개돼 있는데, 흩어져 있고 코드값이라 처음 농사를 시작하는 사람이 읽을 수 없다는 점이 문제의 핵심이라고 봤습니다.
>
> 그래서 새로운 데이터를 만드는 대신 **이미 있는 공공데이터를 필지 단위로 모아 공식 생육 기준과 대조하는 일**에 집중했습니다. AI가 농업 수치를 만들지 않게 하고, 판정은 규칙으로 계산하고 설명만 AI가 맡도록 역할을 나눴습니다.
>
> 값이 없으면 없다고 표시하고, 오래된 자료는 얼마나 오래됐는지 함께 적었습니다. 초보자에게는 그럴듯한 답보다 **확인할 수 있는 근거**가 필요하다고 판단했습니다.

### 이 문안의 의도

- 첫 문장에서 **팀 구성이 주제와 맞는다**는 것을 바로 보여준다
- 두 번째 문장은 문제정의서 원문을 근거로 삼는다. 우리가 임의로 정한 문제가 아니라는 표시다
- 세 번째 문장에서 **5장(책임 분리)의 논지를 미리 심는다**. 소개서 전체가 같은 이야기를 하게 만든다
- 네 번째 문장은 결측·자료 나이 처리라는 실제 구현을 태도로 옮긴 것이다. 과장이 없다

### 개인 이야기를 넣을 자리

`참여 계기`에 개인 경험을 넣으면 더 읽힌다. 다만 **팀원 본인만 쓸 수 있는 내용**이라 초안에 넣지 않았다. 넣을 경우 두 번째 문장 앞에 한 문장으로 붙이는 것을 권한다. 없어도 문안은 완결된다.

## 4. 사진 박스

양식에 `사진` 상자가 있다. 확인이 필요한 항목이다.

- 인물 사진이 없으면 상자를 지우고 표를 넓히는 편이 낫다. 빈 회색 상자가 남는 것이 가장 나쁘다
- 팀 로고나 서비스 아이콘을 대신 넣는 방법도 있다. `밭보다`의 판정서 화면 일부를 잘라 넣으면 3장에서 이미 제품을 보여줄 수 있다

## 5. 확인이 필요한 항목

**역할 분담이 실제 작업 기록과 맞는지 확인해 주세요.**

원안은 `판정 화면 설계`와 `검증`을 남궁도현, `공공데이터 연동`과 `적합도 산출 엔진`을 김택명으로 나눴습니다. 그런데 이 저장소의 2026-07-25 작업 기록을 보면, 김택명 환경에서 다음을 진행한 것으로 남아 있습니다.

- 실시간 연결 4/4 검증과 출처 표 구현
- 토양특성 응답 유실 버그 수정 (표본 24필지 0/24 → 24/24)
- 토양검정 커버리지 조사와 시연 조합 확정
- 결과 화면 4페이지 분리와 문구·용어 정리
- 검증 문서 3건 작성

**소개서 담당업무와 실제 기록이 어긋나면 심사 질문에서 답이 갈립니다.** 개선안은 팀이 준 분담을 그대로 유지했으니, 실제와 다르면 알려 주시면 바로 맞추겠습니다.

그 밖에 확인할 것:

- `5개 API`로 적었다. 팜맵·토양검정 화학성 V2·토양특성 V3·단기예보·농업기상 기본 관측 다섯이다. 화면 출처 표에는 토양 2종을 한 행으로 묶어 `4/4`로 표시하므로, 소개서에서 숫자를 하나로 정해야 한다
- 사진 사용 여부
- 개인 경험 문장 추가 여부
