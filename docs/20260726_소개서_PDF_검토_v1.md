## 0. 먼저 — 코드가 두 갈래로 갈렸다

소개서 4·7·8장은 **Gemini API가 실제로 연결돼 설명 문장을 만들고 검사까지 통과한다**고 쓰고 있다. 그런데 김택명 PC의 현재 소스에는 Gemini 관련 코드가 없다. `lib/report/provider.ts`는 여전히 `현재는 어떤 LLM도 연결하지 않았다` 상태다.

즉 두 갈래가 있다.

| 갈래 | 상태 |
|---|---|
| 남궁도현 환경 | Gemini 연결, 5항목 검사, 실패 후 재시도 사례 확보 |
| 김택명 환경 (어제 전달한 압축 파일) | Gemini 없음. 4페이지 화면 분리, 용어 정리, 규칙 조립 리포트 |

**제출 전에 한쪽으로 합쳐야 한다.** 지금 상태로는 심사가 보는 소개서와 시연 영상에 쓸 코드가 다를 수 있다. 어제 전달한 압축 파일의 `_전달_안내.md`에는 `제공자 미연결`로 적혀 있으므로 그 문서도 함께 정정해야 한다.

## 1. 즉시 수정 — 소개서가 스스로 모순된다

### 1-1. 10장이 4·7·8장을 부정한다 ★가장 시급

10장 표에 이 행이 있다.

> **AI 설명 제공자가 연결되지 않았다** / 규칙으로 조립한 문장을 쓰고, LLM 출력이라고 말하지 않는다 / 어댑터 한 곳 교체 → 출력 검증 통과 시 표시

그런데 4장은 `서비스 안에서도 생성형 AI를 실제로 불러 설명 문장을 만듭니다`, 7장은 `AI가 쓴 설명 (검사 통과)`, 8장은 실제 검사 실패·재시도 사례까지 싣고 있다.

**심사자가 페이지를 넘기면 바로 보이는 모순이다.** AI 활용이 배점 항목(15점)이라 더 위험하다.

이 행은 제가 어제 `미연결` 상태를 기준으로 드린 초안이 그대로 붙은 것이다. **삭제하고 다른 한계로 교체한다.** 대체 후보:

> **AI 문장을 다섯 항목으로만 검사한다** / 판정 인용·금지 표현·새 숫자·구성·길이를 검사하고, 통과하지 못하면 규칙 문장으로 되돌린다 / 근거의 인과를 왜곡하는 경우를 잡는 검사 추가

이 대체안은 8장과 이어지고, 아래 1-3에서 실제로 발견한 문제와도 맞는다.

### 1-2. 공공데이터 개수가 세 가지로 나온다

| 위치 | 표기 |
|---|---|
| 3장 요약설명 | 공공데이터 **네 갈래** |
| 4장 API 표 | 공공데이터 **6개** + Gemini 1개 |
| 7장 자료 상태 | **네 곳** 모두 실시간 응답 |

`네 갈래`를 자료 종류(농지·토양·예보·최근관측)로 쓰고 `6개`를 API 수로 쓴 것이라면 둘 다 맞지만, 소개서만 보는 사람은 숫자가 어긋난다고 읽는다.

**권고**: 용어를 분리해 두 곳 모두 명시한다.

> 자료 네 갈래(농지·토양·예보·최근관측)를 공공데이터 API 6곳에서 조회합니다.

7장 `자료 상태`도 `자료 네 갈래 모두 실시간 응답`으로 바꾸면 4장과 충돌하지 않는다.

### 1-3. 7장 AI 문장에 인과 왜곡이 있다

7장에 실린 AI 문장이다.

> 밭 적성등급이 2급지이고 배수 조건이 '약간 양호'하여 저습하거나 물 고임이 생길 수 있습니다.

세 값 자체는 실제 조회값과 맞다(2급지, 배수 약간 양호, 저해요인 저습). 그런데 인과가 틀렸다.

- **2급지는 좋은 등급**인데 부정적 결과의 근거로 제시됐다
- **`약간 양호`는 양호 쪽**인데 `하여 저습`으로 이어 붙였다. 저습은 배수 등급이 아니라 별도 저해요인 필드값이다

8장이 자랑하는 다섯 항목 검사(판정 인용 / 금지 표현 / 새 숫자 / 구성 / 길이)는 **이런 인과 왜곡을 잡지 못한다.** 숫자를 새로 만들지 않았고 판정도 그대로 인용했기 때문이다.

심사자가 이 문장을 읽고 "AI가 근거를 왜곡하면 어떻게 걸러냅니까"를 물으면 답이 없다. 두 가지 길이 있다.

- **(A) 문장을 교체한다.** 같은 조합으로 다시 호출해 인과가 맞는 출력을 받아 싣는다
- **(B) 이 사례를 강점으로 돌린다.** 8장 `실제 사례`에 두 번째 항목으로 넣고, 10장 한계에 `인과 왜곡 검사 미구현`을 적는다

**(B)를 권한다.** 이미 8장에 실패 사례를 싣는 구조가 있고, 한계를 먼저 말하는 편이 신뢰를 얻는다. 다만 7장 본문은 (A)로 교체해 대표 출력이 깔끔한 상태를 보여주는 편이 낫다.

### 1-4. 9장과 10장의 마무리 문장이 뒤바뀌었다

9장(시행착오) 하단에 이 두 줄이 붙어 있다.

> - 심기 전 현장 확인과 지역 농업기술센터 상담을 대체하지 않습니다.
> - 초보 귀농인이 판단의 근거를 처음으로 손에 쥐는 것이 이 서비스의 목표입니다.

**이 두 문장은 제가 11장(한계와 다음 단계) 마무리용으로 드린 것이다.** 시행착오 장에 붙으면 문맥이 어긋나고, 정작 10장은 표만 있고 마무리 없이 끝난다.

**두 줄을 10장 아래로 옮긴다.** 9장 마무리는 다음 한 줄이 맞다.

> 발견한 문제를 문서로 남기고, 고친 뒤 다시 수치로 확인했습니다.

## 2. 미완성 — 반드시 채워야 할 것

### 2-1. 11장 시연 화면이 비어 있다 ★

양식 placeholder(`서비스 출력 화면 [페이지 추가 가능]`)가 그대로 남아 있다. **프로토타입 증거가 들어갈 자리이고, 예선 평가에서 `구현 가능성 30점`이 걸린 화면이다.**

넣을 것:

1. **판정서 페이지 전체 화면** — 판정 `조건부 적합`, 대상 필지, 3열 근거가 한 장에 보이게
2. **자세한 근거 페이지의 `사용한 자료` 표** — 자료·제공기관·실제 사용한 값·상태·기준시각이 보이면 공공데이터 활용이 증명된다
3. **쉬운 말 리포트 페이지** — 키워드 색 강조가 보이는 부분

세 장을 한 페이지에 나란히 넣거나, 페이지를 나눠도 된다(양식이 추가 허용).

### 2-2. 표지 대괄호가 남아 있다

> 밭보다
> **[**팜맵·토양검정·기상 예보를 필지 단위로 이어 붙인 농지 환경 판정 서비스**]**

양식 placeholder `[한 줄 설명]`의 대괄호다. **제거한다.**

### 2-3. 표지 행사명 확인

표지 하단은 `2026 지역 산업 문제 기반 AI 해커톤`인데 파일명에는 `가톨릭대`가 들어 있다. 공식 명칭을 원문에서 확인해 맞춘다. (관광 프롬프톤 문구는 제거됐다 — 잘 처리했다)

### 2-4. 제출 형식

양식은 `PDF 또는 PPT, PPTX로 저장하여 제출`이라 하고 제출 폼은 **URL**을 요구한다. PDF를 Drive에 올려 링크로 내되 **비로그인 접근**을 반드시 확인한다.

## 3. 가독성 — 심사자가 읽을 수 있어야 한다

### 3-1. 9·10장 표에 마크다운 흔적이 남았다 ★

두 장의 표가 이미지로 붙여져 있고, `요청 데이터 없음`·`자료 없음`·`판정 점수에 넣지 않고 상황 참고용`에 **빨간 배경**이 남아 있다. 마크다운 인라인 코드 스타일이 그대로 캡처된 것이다.

문서에서 복사해 붙인 흔적으로 읽히고, 빨간색이 경고처럼 보여 뜻이 왜곡된다. **표를 슬라이드 네이티브 표로 다시 만든다.** 글자도 지금은 작아서 화면에서 읽기 어렵다.

### 3-2. 3장 `주제 선정 이유`가 너무 작고 길다

3단락 전체가 본문 크기보다 작게 들어가 있다. 슬라이드에서 읽히지 않는다. **3문장으로 줄인다.**

> 귀농 준비자는 `이 땅에 이 작물이 맞는가`를 판단할 근거를 스스로 모으기 어렵습니다. 토양과 기상 자료가 다른 기관에 흩어져 있고, 대부분의 서비스는 시·군 단위 평균값을 보여줍니다.
> 같은 면 안에서도 필지마다 토양 등급과 산도가 다릅니다. 평균값은 `내 땅`의 판단이 되지 않습니다.
> 그래서 지도에서 고른 지점을 필지까지 좁히고, 그 필지의 고유번호로 조회한 값을 공식 생육 기준과 대조했습니다. 없는 값은 채우지 않고 없다고 표시합니다.

지운 내용은 발표에서 말하면 된다.

### 3-3. 4장이 과밀하다

상단 설명 4줄 + 좌우 2열 + 7행 표가 한 장에 있다. 양식이 페이지 추가를 허용하므로 **두 장으로 나누는 것**을 권한다.

- 4-A: 상단 흐름 설명 + AI 도구·데이터 (좌측 열)
- 4-B: 활용 API 표 + Figma

또는 상단 설명 4줄을 2줄로 줄인다.

## 4. 팀 소개(2장) — 어제 드린 개선이 반영되지 않았다

### 4-1. 사진과 자유 서술은 잘 들어갔다

인물 사진이 들어가 빈 상자 문제가 해결됐고, 자유 서술 박스도 채워졌다. 좋다.

### 4-2. 남은 세 가지

| # | 문제 | 권고 |
|---|---|---|
| 1 | `문서/검증 총괄`의 **`총괄`** | 2인 팀에 관리 계층이 없다. `문서 정리와 검증`으로 바꾼다 |
| 2 | **업무 경계가 겹친다** | 남궁도현 `도메인 조사` / 김택명 `문제 정의`가 사실상 같은 일로 읽힌다. 하나로 정리한다 |
| 3 | **`/` 슬래시 표기** | `문서·검증`으로 바꾼다 |

### 4-3. 자유 서술 첫 줄

> "확실한 출처와 근거를 기반으로 개발하는 2인 팀"

따옴표로 감싸 인용처럼 보인다. 자기 소개이므로 따옴표를 빼는 편이 낫다. 그리고 **인공지능학과 2인**이라는 사실이 표 안에만 있다. AI 해커톤에서 팀 구성 자체가 근거이므로 서술 첫 줄로 올릴 것을 권한다.

> 인공지능학과 2인으로, 확실한 출처와 근거를 확인한 뒤에만 반영하는 방식으로 개발했습니다.

## 5. 9장 4번 항목을 교체할 것을 권한다

현재 4번은 이렇다.

> 지도가 결과 화면에서 사라지지 않았다. 숨김 처리가 스타일에 밀렸다 → 숨기는 대신 아예 렌더하지 않도록 변경 → 겹쳐 보이던 높이 2,385px → 0

1~3번이 **설계 재설계 / 데이터 유실 / 데이터 정합성**이라 무게가 있는데, 4번만 내부 렌더링 버그다. `2,385px`는 심사자에게 뜻이 전달되지 않는 숫자다.

**대체 후보** — 유저 친화적 UI/UX 배점과 직결된다.

> **화면이 개발자 말로 쓰여 있었다.** `Mock`·`P0`·`대시보드` 같은 내부 용어와 영어 장식 라벨이 초보자에게 그대로 노출됐다
> → 화면 문구를 전수 점검해 초보자 말로 교체하고, 공식 코드표 용어에는 쉬운 말을 병기(`유효토심 — 뿌리가 뻗을 수 있는 흙 깊이`)
> → 화면에서 내부 용어 **0건**. 한 화면에 쌓였던 결과를 **4페이지로 분리**해 화면마다 정보량을 고정

## 6. 잘된 점

- **8장 `AI 활용`이 이 소개서에서 가장 강한 장이다.** 역할 분리 → 다섯 항목 검사 → 실패 시 되돌림 → 실제 실패 사례 → 마무리 한 줄이 한 장에 정확히 들어갔다. 제가 드린 초안보다 낫다. 실제 검사 실패 사례(`현장 확인 필요` → `현장 확인이 필요합니다`)가 있어 설계가 말이 아니라 구현임이 드러난다
- 표지에서 다른 공모전 문구를 제거했다
- 4장 상단 흐름 설명이 `한 곳이 응답하지 않아도 나머지 결과와 그 사실을 함께 보여줍니다`로 끝난다. 대체 처리를 강점으로 표현한 좋은 문장이다
- 3장 `확인되지 않은 값을 그럴듯하게 채우지 않는다`가 서비스 원칙으로 명시됐다
- 6장 입력·출력 예시에 실제 필지 고유번호를 넣어 구체성이 있다

## 7. 우선순위 정리

마감까지 19시간이므로 순서대로 처리한다.

| 순위 | 항목 | 예상 시간 |
|---|---|---|
| 1 | **10장 `AI 미연결` 행 삭제·교체** (모순 제거) | 5분 |
| 2 | **11장 시연 화면 채우기** | 30분 |
| 3 | **9·10장 마무리 문장 위치 교환** | 5분 |
| 4 | **공공데이터 개수 표기 통일** (3·4·7장) | 10분 |
| 5 | **9·10장 표를 슬라이드 표로 다시 만들기** (빨간 배경 제거) | 30분 |
| 6 | 표지 대괄호 제거, 행사명 확인 | 5분 |
| 7 | 7장 AI 문장 인과 왜곡 처리 (교체 또는 8장으로 이동) | 20분 |
| 8 | 3장 주제 선정 이유 줄이기 | 10분 |
| 9 | 2장 `총괄` 등 문구 정리 | 10분 |
| 10 | 4장 두 장으로 분리 | 20분 |
| 11 | **코드 두 갈래 병합** | 별도 |

1~4번까지만 해도 심사에서 걸릴 지점은 사라진다. 5번 이하는 완성도 문제다.

**11번(코드 병합)은 소개서와 별개로 반드시 처리해야 한다.** 소개서가 Gemini 연결을 전제하므로, 시연 영상도 그 코드로 찍어야 한다.
