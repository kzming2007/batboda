# Codex MVP 제품·UI 설계 v1

> 작성일: 2026-07-23  
> 구현 위치: `prototype/codex-mvp`  
> 참고 원본: `prototype/antigravity-mock`  
> 상태: 1차 구현·실데이터 연결·화면 검증 완료

## 1. 제품 정의

- **구체적 사용자:** 특정 지역 또는 후보 농지를 정하고 첫 작물을 준비하거나 재배를 막 시작했지만, 표준 생육 지식과 실제 토양·최근 기상·예보의 차이를 해석하기 어려운 예비·초기 귀농인
- **사용 상황:** 첫 재배 전부터 초기 활착·초기 생육까지 실제 농지 환경이 작물 기준에 맞는지, 가까운 예보에서 무엇을 먼저 대비해야 하는지 확인하는 순간
- **화면의 단일 임무:** 지역·작물을 받은 뒤 `실제 환경이 표준 생육 기준에 얼마나 맞는가`, `가까운 예보에서 무엇이 위험한가`, `피해 전에 무엇을 확인해야 하는가`를 15초 안에 이해시키는 것

개발자가 보는 API 검증 대시보드가 아니라, 사용자가 결정을 내리는 제품 화면을 만든다.

### 타이포그래피

- **판단·제목:** `IBM Plex Sans KR`, 600~700 — 분석 도구의 정확성과 농업 현장의 실용성을 함께 표현
- **본문·조작:** `Pretendard`, 400~600 — 작은 화면에서도 읽기 쉬운 UI 문장
- **수치·출처·시각:** `IBM Plex Mono`, 400~600 — 단위·시간·데이터 상태를 본문과 구분

글꼴 로딩에 실패해도 한국어 시스템 글꼴로 안전하게 대체한다.

## 3. 레이아웃 비교와 선택

### 후보 A — 일반 카드 대시보드

```text
[제목]
[점수 카드] [위험 카드] [신뢰 카드]
[지도 카드] [차트 카드] [행동 카드]
```

구현은 빠르지만 다른 AI 서비스와 구분되지 않고, 사용자가 판단 순서를 스스로 재구성해야 한다.

### 후보 B — 농지 선택에서 판단까지 이어지는 작업면

```text
┌────────────────────────────────────────────────────┐
│ 내 농지에 이 작물을 심어도 될까?      데이터 상태 │
├──────────────────────────────┬─────────────────────┤
│                              │ 농지 확인            │
│          실제 지도            │ 작물 선택            │
│          + 필지 핀            │ 기간 선택            │
│                              │ [분석하기]           │
└──────────────────────────────┴─────────────────────┘

┌────────────────────────────────────────────────────┐
│ 기초 적합도 ━━━━━ 판단선 ━━━━━ 선택 기간 위험도    │
├──────────────────────┬─────────────────────────────┤
│ 실제값 ↔ 적정범위     │ 위험 타임라인               │
│ 점수 원인             │ 지금 할 행동                │
└──────────────────────┴─────────────────────────────┘
```

후보 B를 선택한다. 사용자가 입력한 농지에서 결과로 시선이 이어지고, 1분 영상의 장면 순서와도 일치한다.

## 4. 고유 시각 요소 — 판단선

결과 화면 상단에 **판단선**을 둔다.

- 왼쪽은 토양·배수·장기환경의 `농지 기초 적합도`
- 오른쪽은 예보기간의 `선택 기간 재배 위험도`
- 중앙 이음부에 데이터 신뢰도와 기준시각
- 아래에는 실제값이 작물 적정범위에서 어디에 놓이는지 같은 축으로 표시

점수 카드 세 개를 나열하는 대신 서로 다른 시간축의 판단을 하나의 선으로 연결한다. 이 한 요소에만 시각적 개성을 집중하고 나머지 화면은 조용하게 유지한다.

## 5. 자체 비평 후 수정

초안의 녹색·베이지·카드 조합은 일반적인 농업 서비스와 유사했다. 다음처럼 수정한다.

- 따뜻한 크림색 대신 약간 차가운 Field Paper를 사용한다.
- 둥근 카드 반복 대신 지도 작업면과 판단선을 화면 구조로 사용한다.
- 장식용 잎·농장 일러스트를 쓰지 않고 필지 경계·범위 막대·시간선처럼 실제 정보를 시각 언어로 사용한다.
- 모션은 분석 완료 시 판단선이 한 번 채워지는 장면에만 사용한다.

## 6. 화면 계약

### 입력

- 지도 핀의 WGS84 위도·경도
- 필지 확인 결과: PNU, 지번, 논·밭 판독
- 작물: 사과, 배, 오이, 감자, 상추
- 재배 방식: 작물별 기본값과 화면 표시
- 분석 기간: 실제 API가 지원하는 프리셋

### 출력

- 농지 기초 적합도와 등급
- 선택 기간 재배 위험도와 위험 시점
- 신뢰도와 데이터 기준시각
- 가장 큰 제한요인 3개
- 실제값·적정범위·단위·출처
- 지금 할 행동 3개
- 한 문장 결론

## 7. 구현 구조

```text
prototype/codex-mvp/
├─ app/
│  ├─ api/analyze/route.ts
│  ├─ api/farm/route.ts
│  ├─ api/soil/route.ts
│  ├─ api/weather/route.ts
│  └─ page.tsx
├─ components/
├─ lib/
│  ├─ public-data/
│  ├─ analysis/
│  └─ mock/
├─ types/
├─ tests/
└─ .env.local
```

- 공공데이터 키는 route handler 안에서만 읽는다.
- 프론트엔드에는 정규화된 필드와 출처·시점만 전달한다.
- Mock과 live는 같은 응답 형식을 사용한다.
- 적합도·위험도는 규칙 기반으로 계산한다.
- LLM은 규칙 결과를 바꾸지 않고 설명만 생성한다.

## 8. 접근성·품질 기준

## 9. 2026-07-23 구현·검증 결과

### 구현 완료

- OpenStreetMap 기반 지도 핀과 평창·영주·이천 시연지 단축 선택
- 사과·배·오이·감자·상추 선택과 기상청 단기예보에 맞춘 1일·3일 기간 프리셋
- 서버 전용 환경변수를 사용하는 팜맵·좌표 기반 토양검정·기상청 단기예보 어댑터
- 공식 밭 적성등급·작물별 pH 기반 재배 판단 단계와 선택 기간 위험을 분리한 규칙 기반 분석
- 판단선, 실제값·공식 범위, 예보 타임라인, 예방 행동, 출처·시점 표시
- 팜맵 후보 목록과 토양 PNU·팜맵 ID의 필지 정합
- API별 독립 실패 처리와 Mock·공공데이터 연결·소스별 대체 상태 구분
- 지도 타일 로딩·실패·재시도 상태와 대표 지역 버튼 대체 경로

### 실행 검증

- 평창 대관령 시연 좌표에서 팜맵 후보 30개와 토양 PNU·경계·pH·유기물·검정일·시료 유형 실응답 확인
- 팜맵 첫 후보 대신 토양 PNU와 일치한 `대관령면 279-15전` 후보가 선택되는 것을 실제 브라우저에서 확인
- 같은 좌표에서 기상청 3일 예보 실응답 확인
- 토양 유기물 단위는 농촌진흥청 토양검정 체계와 맞춘 `g/kg`로 정규화
- 토양특성 V3 공식 코드표로 배수·유효토심·표토토성·토지이용·밭 적성등급·저해요인을 해석
- 밭 적성등급을 주판정 근거로 사용하고 배수는 적합 지수에 중복 감점하지 않으며 선택 기간 위험에만 반영
- 2026-07-24 `v4-stage-first`와 감자 예찰 신호·추가 API 재검증에서 Vitest 30개·ESLint·Next.js production build 통과
- 2026-07-24 감자에 한해 공식 발생환경의 저온·다습·잦은 비 설명을 조합한 역병 환경 신호를 추가했다. 문제정의서 원문 재감사 후 첫 재배 전~초기 사용자에게 맞춰 조건부 예방 참고로 낮췄으며, 공식 예측모형이나 발병 확률로 표시하지 않고 위험 점수에 중복 가산하지 않는다.
- 데스크톱과 375px 모바일에서 지도·선택·분석·실데이터 결과 화면 확인
- 지도 타일 12개 로딩, 지도 상태 오류 없음, 브라우저 콘솔 오류 없음
- 모바일 가로 넘침 없음, `prefers-reduced-motion` 처리
- 프로젝트 루트의 `밭보다_MVP_실행.bat`으로 Node.js·패키지·기존 서버를 확인한 뒤 브라우저까지 여는 실행 경로 제공

### 아직 확정하지 않은 항목

- 다섯 작물의 pH·기온은 `docs/20260723_5개_작물_공식_기준_장부_v1.md`의 농촌진흥청 근거로 교체했다. 유기물은 참고값으로 표시하고 공통 점수에서 제외했다. 감자는 공식 발생환경 설명을 조합한 운영 신호를 추가했으며, 다른 네 작물의 강수·습도 규칙은 후속 병해·생육 단계 검증이 필요하다.
- 현재 위치·주소 검색은 포함하지 않았다. 예선 MVP는 지도 핀과 대표 시연지 선택으로 제한했다.
- 실시간 API 실패 시 실패한 소스만 명시적 Mock으로 대체한다. 제출본에서 사용할 검증 캐시와 갱신 정책은 별도 결정한다.
- LLM API는 연결하지 않았다. 현재 설명은 규칙 결과를 그대로 문장화한 템플릿이며 산식에는 관여하지 않는다.
- 작은 폰트와 낮은 정보 위계·배치 가독성은 2026-07-23 1차 구조 개편으로 보완했다. 다만 제출 화면으로 동결하기 전 실제 사용 흐름, 숫자 지수의 시각적 비중, 모바일·녹화 화면의 가독성을 다시 검토한다. Figma는 이 검토에서 외부 디자인 산출물이 필요한 경우에만 사용한다.
- 2026-07-24 팀 결정에 따라 결과 화면의 주결론은 `적합 / 조건부 적합 / 현장 확인 필요` 단계로 고정한다. 100점 숫자는 판정을 대신하지 않으며, 공식 기준과 운영 규칙이 어떻게 적용됐는지 보여주는 보조 계산 근거로 낮춘다.
- 같은 단계에서 화면 카피도 전수 점검한다. `MODEL STATUS`, `CALCULATION LEDGER`, `근거 충족도` 같은 내부·장식 용어는 사용자의 질문에 직접 답하는 한국어로 바꾸고, 과장된 AI 문구나 불필요한 의인화를 사용하지 않는다. 단, 공식 데이터명과 코드값은 숨기지 않고 쉬운 설명과 원문을 함께 제공한다.
- 현재 Next.js Mock도 Node.js가 필요하다. 소스 공유 시 `node_modules`·`.next`·`.env.local`은 제외하며, 설치 없는 공유는 배포 URL을 기본안으로 둔다.
- 결과 화면은 단계 결론→핵심 원인→토양 적합·선택 기간 위험 지수→계산 장부 순으로 읽히게 한다. 근거 충족도는 세 번째 100점 카드 대신 연결·결측·이상치를 함께 보여주는 5칸 근거 표식으로 구분한다.
- 미확정 후보로 PASS·금융 앱의 인증 시작 화면처럼 정돈된 기본정보 입력 온보딩을 검토한다. 이는 회원가입·로그인·본인인증 기능이 아니라 위치·작물·기간 입력을 단계적으로 안내하는 표현 방식이다. 대시보드 바로 진입보다 이해가 빠른지와 1분 시연 시간을 낭비하지 않는지를 비교하기 전에는 구현 범위로 확정하지 않는다.
