## 3. 팀 결정 (2026-07-25)

1. 영상 안정성을 위해 **검증 캐시 도입** — 실시간 우선, 실패 시 스냅샷, 화면에 수집시각·출처 표시
2. **LLM은 계약만 구현**하고 제공자는 연결하지 않음. 화면은 규칙 기반 설명
3. **배포 URL은 만들지 않음** — 제출물은 소개서 URL + 영상 URL
4. UI는 부분 개선이 아니라 **디자인 언어 교체**. Figma에서 A(에디토리얼)·B(다크 계기판) 비교 후 **A안 확정**
5. 판정 색 규칙: `적합=딥그린 / 주의·기준 이탈=클레이 레드 / 토양 수치=골드`
6. 중기예보(3~10일)는 API 미연결이므로 화면에서 제외. 넣으려면 활용신청부터 필요

5. **초보자 설명을 LLM 연결성이 드러나게 확장 검토** (중간 비용)

   지금은 3블록 규칙 문장이고 제공자는 미연결이라, 화면만 보면 LLM 역할이 잘 보이지 않는다. 검토할 방향은 다음과 같다.

   - 같은 근거 묶음으로 만든 `규칙 문장`과 `AI 문장`을 나란히 보여주고, 연결 전에는 AI 칸을 `연결 시 이 자리에 들어갑니다`로 비워 두는 형태
   - 행동 항목별 설명을 LLM이 다시 쓰는 경로(현재 `actionNotes`가 이미 분리돼 있어 확장 지점이 준비됨)
   - 사용자가 `더 쉽게 설명` 같은 재요청을 눌러 같은 근거로 다른 문장을 받는 흐름
   - 확장하되 검증 계약은 그대로 유지한다. 판정·수치 변경 금지, 실패 시 규칙 문장 대체
   - 선행 조건: 리포트 검증의 숫자 화이트리스트에 예보 날짜·값을 포함시켜야 정상 문장이 반려되지 않는다

6. **결과의 객관적 평가 가능성 검토** (본선 대비)

   현재는 구현 민감도 감사만 있고 현장 정확도 근거가 없다. 다음 단계로 검토할 항목.

   - 정답 라벨을 어디서 얻을지: 농업기술센터 상담 사례, 작목별 재배 적지 자료, 실제 재배 성공·실패 기록 등 확보 가능한 후보를 먼저 조사
   - 평가 방식 후보: 같은 필지·작물에 대한 전문가 판정과 우리 단계 판정의 일치율, 등급 경계 부근 사례의 오분류 방향(보수적 오류 우선 여부)
   - 설명 품질 평가: 규칙 문장과 AI 문장을 사람이 블라인드로 비교(이해도·정확성·과장 여부)
   - 지금 시점에는 `정확도 미검증`을 그대로 표기하고, 평가 설계만 문서로 남긴다. 검증되지 않은 정확도 수치를 만들지 않는다

7. 여유가 있으면 `분석 진행 단계 표시`, `작물 기준 미리보기` (둘 다 낮은 비용)
8. 본선 항목으로 미룸: 필지 경계 폴리곤 표시, 첫 화면 온보딩, 위험 등급 보정
