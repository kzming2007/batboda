# 문제정의서 핵심 요구사항 감사와 시연 조합 확정

> 작성일: 2026-07-25
> 근거: 문제정의서 1 `4. 핵심 요구사항` 원문과 실호출 측정. 측정은 모두 실시간 공공데이터 응답이다.
> 단일 기준 문서는 `docs/RISE_AI_해커톤_예선_준비_통합.md`이며 충돌 시 기준 문서를 따른다.

## 1. 결론

**구현은 ①②④를 충족하고 ③ LLM 리포트가 미충족이다.** 부분 미충족은 중기예보와 최근 추이 반영 두 곳이다.

시연 조합은 **`대관령면 85-61전` + `상추`** 로 확정하는 것이 좋다. 90조합을 실측한 결과 유일하게 판정이 `조건부 적합`으로 나오고 모든 자료가 채워지는 조합이다.

## 2. 항목별 감사

### ① 실시간 공공 데이터 연동 — 충족 (기상 일부 미충족)

| 요구 | 구현 | 판정 |
|---|---|---|
| 토양 API → 토성 | 토양특성 V3 표토 토성 (세사양토·식양토 등 공식 라벨) | 충족 |
| 토양 API → pH | 토양검정 화학성 V2 `ACID` | 충족 |
| 토양 API → EC | 토양검정 화학성 V2 `ELCD`, dS/m | 충족 |
| 기상 API → 최근 기후 추이 | 농촌진흥청 농업기상 기본 관측 최근 7일 | 충족 |
| 기상 API → 단기예보 | 기상청 단기예보 3일 | 충족 |
| 기상 API → **중기예보** | 미연결 | **미충족** |

요구사항 예시는 `스마트팜코리아, 흙토람`이다. 우리는 흙토람 계열(농촌진흥청 토양검정·토양특성)을 쓰고 스마트팜코리아는 쓰지 않는다. 대신 팜맵으로 필지를 확정한 뒤 PNU로 조회하므로 행정구역 평균이 아니라 필지 단위다. 요구를 좁게가 아니라 더 정밀하게 만족한다.

중기예보(3~10일)는 2026-07-25 팀 결정 6번으로 제외했다. 활용신청이 선행되어야 한다.

### ② 환경 적합도 산출 로직 — 충족

| 요구 | 구현 | 판정 |
|---|---|---|
| 표준 생육 지침과 비교 | 5작물 pH·기온 범위를 농업기술길잡이 판·쪽수까지 기록 | 충족 |
| 룰 기반 알고리즘 | 규칙 엔진(`lib/analysis/engine.ts`), LLM은 수치에 개입 못 함 | 충족 |
| 적합도 점수 또는 시각화 | 적합도 점수 + 판정 단계 + 3열 근거 + 계산 근거 원장 | 충족 |

우리는 점수보다 **판정 단계를 앞세운다**(`v4-stage-first`). 점수는 비교용 보조값으로 표기하고, 공식 기준에서 온 값과 자체 설계 가중치를 항목마다 구분한다. 요구사항이 `점수 또는 대시보드`이므로 충족한다.

#### 핵심 요구사항 Tip 다섯 항목

| Tip | 구현 | 실측 근거 | 판정 |
|---|---|---|---|
| 가중치 설계 | `scoreExplanations`에 항목별 formula와 term, 공식/자체 구분 표기 | 화면 `계산 근거` 3개 원장 | 충족 |
| 범위 밖 정도 차등 | 이탈 거리 × 작물 민감도 | 상추 기준 6.5–7.0에서 pH 6.9 `good` 90점 / 7.1 `watch` 83점 / 7.5 `risk` | **충족(실증)** |
| 작물별 민감도 차이 | `sensitivity` 3단계 + 근거 문장 | 같은 필지 85-61전에서 상추 90 / 배 77 / 사과 64 / 오이 61 | **충족(실증)** |
| 시계열·예측 처리 | 단기예보 3일이 위험 점수에 반영. 최근 7일 관측은 화면 표시만. 중기예보 없음 | 야간 저온은 3일 최저기온으로 확인 | **부분 충족** |
| 결측·이상치 처리 | 결측 감점, 허용범위 밖 값 제외, 신뢰표시 하락, `자료 없음` 표기 | pH 결측 필지에서 신뢰 100 → 84 | 충족 |

시계열 항목이 부분 충족인 이유는 7절에 적은 대로 `recentClimate`가 적합도·위험 점수에 들어가지 않기 때문이다. 화면에는 최근 7일 누적강수·기온·습도가 나오지만 판정 숫자에는 기여하지 않는다.

### ③ LLM 기반 리포트 — 미충족

요구는 `추출된 분석 결과를 생성형 AI와 결합해 초보 귀농인 눈높이의 자연어 가이드라인 생성`이다.

구현된 것은 계약뿐이다. 근거 묶음, 프롬프트 규칙, 출력 검증(판정·수치 변경 금지), 실패 시 규칙 문장 대체까지 모두 있고 **제공자만 비어 있다.** 지금 화면 문장은 전부 규칙 기반이다.

`lib/report/provider.ts`는 어댑터 하나를 등록하면 되는 구조다.

```
export type ReportProvider = {
  name: string;
  generate: (input: { system: string; user: string }) => Promise<string>;
};
```

즉 남은 작업은 `generate` 한 함수와 키 설정이다. 계약·검증·대체는 건드리지 않는다.

예선 배점에 `AI 활용 15점`이 있으므로 이 항목이 가장 큰 갭이다.

### ④ 유저 친화적 UI/UX — 대체로 충족

| 요구 | 구현 | 판정 |
|---|---|---|
| 전문 용어 치환 | 코드값을 공식 라벨로 변환(`04` → `4급지`, `02` → `경사`, `세사양토`) | 충족 |
| 시각 요소 | 판정 색 규칙, 신호 점, 3열 근거, 예보 게이지 카드 | 충족 |
| EC 설명 | `전기전도도(EC)` + dS/m + `참고값 · 점수 미반영` 명시 | 부분 |
| 유효인산 | 미사용 | 미충족 |

EC·유기물은 노출하고 단위를 붙였지만 `높다/낮다`처럼 직관적으로 치환하지는 않았다. 작물별 기준이 확인되지 않아 점수에서 제외한 항목이라 판단을 붙이지 않은 것이다. 유효인산은 토양검정 V2 응답에 있으나 쓰지 않는다.

## 3. 시연 조합 확정

### 토양검정 화학성 커버리지

반경 1km 후보 356건의 고유 PNU 258건에 토양검정 화학성 V2를 전수 조회했다.

| | 건수 |
|---|---|
| 검정 이력 있음 (pH 확보) | **18건** |
| 요청 데이터 없음(301) | 240건 |
| 커버리지 | **7.0%** |

`getSoilExam`은 `PNU_CD`만 받는다. 법정동코드로 넓혀 조회하는 방법을 실호출로 확인했으나 `204 필수 요청변수 미입력`으로 거부된다. 즉 **필지별 검정 이력이 없으면 pH를 얻을 방법이 없다.**

### 90조합 실측

검정 이력 18필지 × 5작물 = 90조합을 실시간으로 돌렸다.

| 판정 | 건수 |
|---|---|
| 현장 확인 필요 | 86 |
| **조건부 적합** | **4** |

조건부 적합이 나온 네 조합.

| 필지 | 작물 | 적합도 | 밭 적성 | pH | pH 상태 | 위험 | 신뢰 |
|---|---|---|---|---|---|---|---|
| **85-61전** | **상추** | **90** | **2급지** | **6.9** | **good** | 주의 | **100** |
| 201-7전 | 상추 | 83 | 2급지 | 7.1 | watch | 주의 | 100 |
| 279-18전 | 상추 | 75 | 3급지 | 6.7 | good | 주의 | 100 |
| 279-18전 | 배 | 69 | 3급지 | 6.7 | watch | 높음 | 100 |

감자는 최고 60점(85-22전, pH 5.8 good, 4급지)으로 전부 `현장 확인 필요`다. 대관령 밭은 pH가 6.6~7.7로 중성~약알칼리인데 감자 공식 기준이 5.0~6.0이라 구조적으로 맞지 않는다.

### 확정: 85-61전 + 상추

| 항목 | 값 |
|---|---|
| 필지 | 대관령면 85-61전 (PNU 5176038024100850061) |
| 작물 | 상추 (공식 pH 6.5–7.0) |
| 판정 | 조건부 적합 · 적합도 90 |
| 밭 적성등급 | 2급지 |
| pH | 6.9 (기준 안, `good`) |
| 선택 기간 위험도 | 주의 |
| 신뢰표시 | 100 · 실시간 연결 4/4 |

이 조합을 쓰는 이유.

1. **판정이 한쪽으로 쏠리지 않는다.** `조건부 적합`이면서 위험은 `주의`라, 적합도와 단기 위험이 서로 다른 축이라는 설계가 한 화면에 드러난다. 모든 필지가 `현장 확인 필요`로만 나오면 심사위원이 로직이 작동하는지 확인할 수 없다.
2. **모든 자료가 채워진다.** 신뢰표시 100, 4/4, pH·유기물·EC·밭 적성등급·저해요인·배수·유효토심·표토 토성 전부 값이 있다.
3. **작물별 민감도를 즉석에서 보여줄 수 있다.** 같은 필지에서 작물만 바꾸면 상추 90 → 배 77 → 사과 64 → 오이 61로 갈린다. Tip의 `작물별 민감도 차이`를 말이 아니라 화면으로 증명한다.
4. **범위 밖 정도 차등도 보여줄 수 있다.** 상추로 고정하고 필지만 바꾸면 pH 6.9 `good` 90점 → 7.1 `watch` 83점으로 갈린다.

기존에 검토했던 279-15전은 pH 7.0이 감자 기준을 벗어나 28점이고 EC 5.87 dS/m이 다른 필지(0.05~1.18)에 비해 이례적으로 높다. 시연 필지로 쓰지 않는다.

## 4. 남은 갭과 권고

| 갭 | 배점 영향 | 비용 | 권고 |
|---|---|---|---|
| ③ LLM 제공자 미연결 | AI 활용 15점 직결 | 낮음 — 어댑터 1개 + 키 | **최우선 착수** |
| 중기예보 미연결 | 구현 가능성 | 높음 — 활용신청 필요 | 예선에서는 제외 유지, 소개서에 로드맵으로 |
| 최근 추이 점수 미반영 | 구현 가능성 | 중간 | 산식 수정보다 **표현을 사실에 맞추기**. `최근 관측을 함께 보여준다`로 쓴다 |
| 유효인산 미사용 | 낮음 | 낮음 | 예선에서는 생략 유지 |

LLM 연결 시 선행 조건이 하나 있다. 리포트 검증의 숫자 화이트리스트가 예보 날짜·값을 막을 수 있어, 정상 문장이 반려되지 않도록 화이트리스트에 포함시켜야 한다(인수·인계 5절).

## 5. LLM 기반 리포트 탭 (2026-07-25 추가)

팀 결정으로 **실제 LLM을 연결하지 않고, 연결됐을 때 나올 리포트를 미리 작성해 보여주는 탭**을 만들었다. 키·비용·검증을 마감 안에 처리하지 않고도 ③ 요구사항의 결과물 형태를 심사에 보여주는 것이 목적이다.

### 위치와 구조

`자세한 근거 보기` 접기 바로 아래에 두 번째 접기 `LLM 기반 리포트`를 추가했다. 판정서의 마지막 블록이다.

구성은 다음과 같다.

1. `시연용 예시 문안 · 생성 제공자 미연결` 배지
2. 실제 AI 출력이 아님을 밝히는 고지 문단
3. 한 문장 결론
4. `이 땅의 흙은 어떤가요` / `지금 날씨는 어떤 부담을 주나요` / `이 판단의 한계`
5. `심기 전에 확인할 일` 번호 목록 (행동 항목마다 왜 지금 하는지 풀어 씀)
6. 마무리 한 문장
7. `이 글이 인용한 값` 칩 — pH, 밭 적성등급, 적합도, 위험도, 기간

### 표시 원칙

**예시임을 숨기지 않는다.** 배지와 고지 문단을 항상 함께 보여준다. 심사에서 `이게 실제 LLM 출력인가`를 물었을 때 표시가 없으면 오히려 감점 요인이고, 이 프로젝트 규칙도 `실시간·캐시·시연용 샘플을 화면에 명확히 표시한다`다. 인수·인계 4절 5항의 `연결 시 이 자리에 들어갑니다` 구상과 같은 방향이다.

고지 문단은 다음을 명시한다. 제공자를 연결하면 같은 근거 묶음으로 생성 문장이 이 자리에 들어가고, 판정·수치를 바꾸지 않았는지 검증을 거친 뒤 표시되며, 검증 실패 시 규칙 기반 설명으로 되돌린다.

### 열리는 조건

**pH와 밭 적성등급이 모두 조회된 필지에서만 문안을 만든다.** 둘 중 하나라도 없으면 문장을 채우지 않고 이유를 적는다.

| 사례 | 결과 |
|---|---|
| 85-61전 + 상추 | 문안 있음 (손으로 다듬은 대표 사례) |
| 85-22전 + 감자 | 문안 있음 (손으로 다듬은 대표 사례) |
| 201-7전 + 상추 | 문안 있음 (조립 문안, pH `watch` 반영) |
| 294-39전 + 감자 | **문안 없음** — `토양검정 이력이 없어 pH를 조회하지 못했습니다. … 없는 값을 문장으로 채우지 않습니다.` |

3절에서 확인한 검정 이력 18필지가 이 탭이 열리는 대상이다.

### 수치 취급

문안은 **규칙 엔진이 확정한 값만 인용하고 새 수치를 만들지 않는다.** pH, 밭 적성등급, 저해요인·배수·유효토심·표토 토성, 기온 평균과 공식 적온, 강수확률, 최근 7일 누적강수·강수일, 검정 시점, 시료 유형 모두 분석 응답에서 끌어온다. 발병 확률·수확량·성공 가능성은 말하지 않는다.

최근 7일 관측을 인용할 때는 `판정 점수에 넣지 않고 상황 참고용으로만 보여드립니다`를 함께 적었다. 7절에서 확인한 `최근 추이 점수 미반영`과 문장이 어긋나지 않게 하려는 것이다.

### 문안 조립 방식

작물별로 공식 기준의 의미를 풀어 쓴 문장(`cropVoice`), 밭 적성등급 구간별 문장(`gradeVoice`), pH 상태별 문장, 행동 항목별 문장(`actionVoice`)을 조합한다. 대표 사례 두 건은 `PNU:작물` 키로 손으로 쓴 도입 문단을 우선 적용한다.

과장을 피하려고 두 곳을 다듬었다.

- 85-61전 도입부에서 `흙 쪽에서 특별히 손볼 곳이 없다`를 `산도가 권장 범위 안에 있고 밭 등급도 좋은 편`으로 바꿨다. 이 필지는 저해요인이 `저습`이라 흙 전체를 낙관할 근거가 없다.
- 마무리 문장에서 저해요인이 실질적으로 걸린 필지는 `산도는 맞습니다. 남은 것은 저해요인으로 적힌 ○○과 날씨입니다`로 끝내도록 했다.

한국어 조사도 받침에 따라 고르게 했다. `주의으로` → `주의로`, `경사과` → `경사와`, `pH 7.1를` → `pH 7.1을`. 숫자는 마지막 자리의 한글 읽기를 따른다.

### 실제 출력 (85-61전 + 상추, 실시간)

> 결론부터 말하면, 이 땅에 상추를 심는 것은 지금 자료로는 무리가 없어 보입니다. 산도가 상추 권장 범위 안에 있고 밭 등급도 좋은 편이라, 흙을 바꾸는 일부터 시작할 필요는 없습니다. 다만 흙 조건이 좋다는 것과 지금 심기 좋다는 것은 다른 이야기입니다. 아래 저해요인과 날씨 부분을 함께 보셔야 합니다.

마무리: `정리하면 산도는 맞습니다. 남은 것은 저해요인으로 적힌 저습과 고른 기간의 날씨입니다. 이 둘은 흙을 바꾸는 문제가 아니라 관리로 다루는 문제입니다.`

인용한 값: pH 6.9 / 밭 적성등급 2급지 / 적합도 90 / 위험도 62 / 기간 3일
