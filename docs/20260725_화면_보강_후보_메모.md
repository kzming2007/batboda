# 화면 보강 후보와 실행 가능성 메모

> 작성일: 2026-07-25
> 갱신: 2026-07-25 (Figma 활용 가능 확인, A안 적용 반영)
> 기준: 07-27 18:00 마감. 남은 필수 작업은 녹화 리허설, 1분 영상, 서비스 소개서다.
> 상태: UI 디자인 언어는 A안으로 확정·적용했고, 아래 1절 후보는 여전히 미결정이다.

## 1. 후보별 실행 가능성

| 후보 | 가능한가 | 필요한 작업 | 예상 비용 | 실패 위험 |
|---|---|---|---|---|
| 분석 진행 단계 표시 | 가능 | 분석 API를 소스별 단계로 나누거나, 클라이언트에서 팜맵→토양→예보→판정 순서를 진행 표시로 보여준다. 실제 호출 순서는 이미 서버에 있으므로 표시만 추가하면 된다 | 낮음 | 낮음. 실제 호출과 표시가 어긋나지 않게 소스별 상태값을 그대로 써야 한다 |
| 작물 기준 미리보기 | 가능 | `lib/analysis/cropProfiles.ts`에 이미 작물별 pH·기온 범위와 출처가 있다. 입력 화면의 작물 카드에 펼쳐 보이면 된다 | 낮음 | 낮음 |
| 지도에 필지 경계 표시 | 조건부 가능 | 팜맵 후보 응답에 도형 좌표가 있는지 실호출로 먼저 확인해야 한다. 현재 어댑터는 주소·PNU·팜맵 ID만 뽑고 좌표를 버린다. 토양 API의 GML 경계는 존재 여부만 확인하고 파싱하지 않았다. EPSG:5179 → WGS84 변환도 필요하다 | 높음 | 중간~높음. 응답 구조 확인, 좌표 변환, Leaflet 폴리곤 렌더까지 세 단계가 모두 성공해야 한다. 오늘 착수하면 영상·소개서 시간을 침범할 수 있다 |
| 첫 화면 온보딩(PASS식 단계 입력) | 가능 | 지금 한 화면에 있는 위치·작물·기간 입력을 단계로 나눈다 | 중간 | 중간. 1분 영상에서 입력 장면이 길어져 분석·결과 시간이 줄어든다. 기준 문서에서도 미확정 아이디어로만 남겨 둔 항목이다 |

권장 순서는 `분석 진행 단계 표시` → `작물 기준 미리보기`다. 둘 다 실패 위험이 낮고 영상에서 공공데이터와 공식 기준 사용이 눈에 보이게 만든다. 필지 경계는 본선용 항목으로 미루는 것이 안전하다.

## 2. Figma 활용 (2026-07-25 갱신)

**사용 가능하다.** 앞서 `커넥터 없음 · 코드→디자인 불가`로 적었던 판단은 정정한다. Figma MCP 커넥터를 연결한 뒤 실제로 다음을 확인했다.

- 디자인 파일 생성 (`create_new_file`) — 학생 플랜 Collab 시트로도 동작
- Plugin API 실행으로 화면 시안 작성·수정 (`use_figma`), 스크린샷 확인 (`get_screenshot`)
- 다이어그램 생성(`generate_diagram`), 에셋 추출(`download_assets`)도 사용 가능

실제 활용 결과는 다음과 같다.

1. `밭보다 UI 시안 v1` 파일에 세 가지 시안을 만들었다 — 간소화 대시보드, **에디토리얼 판정서(A)**, 다크 계기판(B)
2. 팀은 A안을 확정했고, 시안에서 3열 정렬·색 규칙·글자 크기를 조정한 뒤 코드에 적용했다
3. 시안 → 코드 이관은 자동 변환이 아니라 사람이 확인한 규칙(세리프 대형 판정, 룰 라인, 3열 근거, 접기 근거)을 손으로 옮기는 방식으로 했다. 데이터 계약이 깨지지 않는 선에서 표시 계층만 바꿨다

남은 활용처는 소개서용 아키텍처 다이어그램과 화면 캡처다. 소개서 본문은 공식 Google Slides 양식을 써야 하므로 Figma Slides로 대체하지 않는다.

## 2-1. 녹화 전 최종 검증 항목 (필수)

**시연 영상을 실시간 공공데이터 연동 화면으로 녹화할 수 있는지 녹화 직전에 반드시 확인한다.** 확인하지 않으면 화면에 `시연용 검증 자료` 또는 `검증 스냅샷` 배지가 남은 상태로 녹화될 수 있다.

체크 순서는 다음과 같다.

1. `.env.local`에 인증키가 있고 `실제 공공데이터로 조회` 스위치가 켜지는지
2. 대표 좌표(`37.675, 128.718`)에서 반경 1km 농지 후보가 조회되는지 — 2026-07-24 16:25에는 반경 250~500m에서 `NODATA_ERROR`가 났고 1km에서 복구됐다
3. 지번 검색으로 `279-15`를 찾아 필지를 확정할 수 있는지
4. 확정한 PNU로 토양검정·토양특성이 조회되는지
5. 단기예보와 최근 농업기상이 응답하는지
6. 결과 화면 상단이 `공공데이터 연결`이고 `실시간 연결 4/4`인지
7. 4/4가 아니면 어느 소스가 실패했는지 기록하고, 검증 스냅샷으로 대체된 상태를 그대로 녹화할지 팀이 결정

`4/4`가 아닐 때의 대비도 함께 정한다. 실패 소스가 있어도 화면은 대체 사실을 표시하도록 구현돼 있으므로, 숨기지 않고 그대로 보여주는 편이 운영 가능성 항목에 유리하다. 다만 영상에서 어떤 상태로 보여줄지는 녹화 전에 확정해야 한다.

## 3. 결론

- 남은 시간은 녹화 리허설과 소개서에 쓴다. 녹화 전 2-1절 검증을 반드시 통과시킨다.
- 화면 보강은 1절의 낮은 비용 두 항목(분석 진행 단계 표시, 작물 기준 미리보기)만 팀 확인 후 착수한다.
- 필지 경계 표시와 첫 화면 온보딩은 본선 준비 항목으로 넘긴다.
- Figma는 계속 사용한다. 다음 용도는 소개서용 아키텍처 다이어그램과 화면 캡처다.
