# 서비스 소개서 5·9·11장 초안

> 작성일: 2026-07-26
> 대상: 추천 구성 11장 중 **5장(아키텍처: 책임 분리)**, **9장(시행착오와 개선)**, **11장(한계와 다음 단계)**
> 5·9·11장은 공식 양식에 전용 슬롯이 없다. 양식 1장이 `정해진 양식 이 외에 페이지 추가해서 사용하셔도 됩니다`라고 허용한 추가 페이지다.
> 슬라이드에 올릴 문구와 발표용 보충 설명을 나눠 적었다. **슬라이드에는 `[슬라이드]` 블록만 옮긴다.**
> 모든 수치는 이 프로젝트에서 실측·검증한 값이며 근거 문서를 함께 적었다.

## 5장 — 아키텍처: 책임 분리

### 이 장의 목적

심사 배점 `구현 가능성 30점`과 `AI 활용 15점`을 한 장에서 받는 자리다. **AI가 무엇을 하고 무엇을 하지 않는지**를 분명히 하는 것이 핵심이다. 기능 나열이 아니라 책임 경계를 보여준다.

### [슬라이드] 제목

> **판정은 규칙이, 설명은 AI가**

### [슬라이드] 부제 한 줄

> 숫자를 만드는 곳과 말을 만드는 곳을 분리했습니다.

### [슬라이드] 흐름도 (가로 5단계)

```
①  입력              ②  공공데이터 조회        ③  규칙 기반 계산
   농지 위치            팜맵 · 토양 2종            공식 기준과 대조
   작물 · 기간          예보 · 농업기상            판정 단계 확정
                       4곳 독립 호출              수치 확정
        │                    │                        │
        └────────────────────┴────────────────────────┘
                             ↓
④  설명 생성                          ⑤  화면
   확정된 값만 받아 문장으로              판정 · 근거 · 출처
   수치를 새로 만들 수 없음               자료 상태 표시
```

### [슬라이드] 책임 경계 표 — 이 장의 핵심

| 구분 | 규칙 엔진 | AI 설명 계층 |
|---|---|---|
| 판정 단계 | **결정한다** | 바꿀 수 없다 |
| 수치 (pH·등급·점수) | **결정한다** | 인용만 한다 |
| 공식 기준 대조 | **한다** | 하지 않는다 |
| 초보자용 문장 | 하지 않는다 | **만든다** |
| 검증 실패 시 | — | 규칙 문장으로 되돌린다 |

### [슬라이드] 이렇게 만든 이유 (3줄)

> - AI가 농업 수치를 만들면 **틀렸는지 확인할 방법이 없습니다.**
> - 공식 기준 대조는 규칙으로 하면 **같은 입력에 같은 결과**가 나옵니다.
> - AI는 그 결과를 초보자가 읽을 수 있게 옮기는 일만 맡습니다.

### [슬라이드] 구현 상태 (작게, 우하단)

> 규칙 엔진·근거 묶음·출력 검증·실패 시 대체 경로 구현 완료 · 자동 테스트 41개 통과
> 생성 제공자는 어댑터 한 곳만 교체하면 연결됩니다

### 발표용 보충 설명 (슬라이드에 넣지 않음)

- 실제 모듈 경계: 공공데이터 호출 `lib/public-data/`, 판정 `lib/analysis/engine.ts`, 작물별 공식 기준과 출처 `lib/analysis/cropProfiles.ts`, 토양도 코드 해석 `lib/analysis/soilCodes.ts`, 자체 설계 계수·임계값 `lib/analysis/modelPolicy.ts`, 근거 묶음 `lib/report/bundle.ts`, 출력 검증 `lib/report/contract.ts`, 제공자 어댑터 `lib/report/provider.ts`
- 코드 규모: TypeScript 27개 파일 약 5,000줄, 자동 테스트 8개 파일 41개
- 4개 API를 하나씩 독립 호출하므로 **한 곳이 실패해도 나머지는 살아남는다.** 실패한 소스만 `대체 자료`로 표시한다
- `자체 설계 계수·임계값`은 공식 기준이 아니라 이 서비스가 정한 값이며, 화면에서 공식 기준과 구분해 표시한다

## 9장 — 시행착오와 개선

### 이 장의 목적

공식 안내가 요구하는 항목인데 양식에 슬롯이 없다. **처음 만든 것을 완성본으로 두지 않았다는 증거**를 보여주는 자리다. 실패를 숨기지 않는 편이 `구현 가능성`과 `운영 가능성`에 유리하다.

### [슬라이드] 제목

> **네 번 뒤집었습니다**

### [슬라이드] 부제 한 줄

> 첫 결과를 완성본으로 두지 않고, 발견한 문제마다 수치로 확인했습니다.

### [슬라이드] 4건 표 — 발견 → 조치 → 확인

| # | 발견한 문제 | 조치 | 확인한 결과 |
|---|---|---|---|
| 1 | **점수 임계값 방식이 흔들렸다.** 감점 폭을 ±20%만 바꿔도 적합도 등급이 16.4~20.0% 달라졌다 | 점수로 등급을 정하는 방식을 폐기하고, **공식 밭 적성등급과 pH 상태로 판정 단계를 직접 정하도록** 재설계 | 같은 560개 시나리오에서 주판정 변동 **0%** |
| 2 | **주 판정 근거가 비어 있었다.** 밭 적성등급이 계속 `자료 없음`으로 나왔다 | 토양검정이 `요청 데이터 없음`이면 **정상 응답한 토양특성까지 함께 버리던 코드**를 수정 | 표본 24필지에서 **0/24 → 24/24** 조회 성공 |
| 3 | **다른 필지의 토양값이 붙을 수 있었다.** 캐시 좌표 허용 오차가 0.02°(약 2km)로 넓었다 | 오차를 **0.002°로 좁히고**, 사용자가 필지를 확정했으면 **필지번호 일치를 요구** | 확정 필지와 다른 토양값이 붙는 경로 차단 |
| 4 | **지도가 결과 화면에서 사라지지 않았다.** 숨김 처리가 스타일에 밀렸다 | 숨기는 대신 **아예 렌더하지 않도록** 변경 | 겹쳐 보이던 높이 **2,385px → 0** |

### [슬라이드] 이것도 바꿨습니다 (작게, 3줄)

> - 화면 문구 감사 — `Mock`·`P0`·`대시보드` 같은 내부 용어를 초보자 말로 교체
> - UI를 부분 수정에서 **디자인 언어 교체로 전환** — 두 시안을 만들어 비교한 뒤 확정
> - 한 화면 스크롤을 **4페이지로 분리** — 화면마다 정보량을 고정

### 발표용 보충 설명 (슬라이드에 넣지 않음)

- 1번은 `docs/20260724_적합도_엔진_민감도_감사.md`. 560개는 합성 시나리오이며 **구현 민감도 감사이지 현장 정확도 검증이 아니다.** 발표에서 이 구분을 반드시 말한다
- 2번은 병렬 호출 결과를 기다리기 전에 항목을 꺼내던 실수였다. 근거는 `docs/20260725_2차PC_환경재현과_실시간검증_v1.md` 8절
- 4번은 브라우저 기본 숨김 규칙이 작성자 스타일에 우선순위로 밀린 사례다. 속성값만 확인하고 실제 렌더를 확인하지 않아 한 번 놓쳤다
- 시안 비교 결과와 규칙은 `기준 문서` 119~120행. 교체로 쓰이지 않게 된 CSS 121개 블록을 제거했다

## 11장 — 한계와 다음 단계

### 이 장의 목적

`운영 가능성 25점`이 걸린 자리다. 한계를 먼저 말하는 편이 신뢰를 얻는다. **지금 못 하는 것과 다음에 할 것을 짝지어** 보여준다.

### [슬라이드] 제목

> **지금 못 하는 것을 먼저 말합니다**

### [슬라이드] 부제 한 줄

> 이 서비스는 참고 판단을 제공합니다. 수확량이나 성공 가능성은 말하지 않습니다.

### [슬라이드] 한계 → 다음 단계 표

| 지금의 한계 | 화면에서 어떻게 다루는가 | 다음 단계 |
|---|---|---|
| **토양검정 이력이 있는 필지가 적다.** 대관령 반경 1km 258필지 중 pH가 나오는 필지는 18건(7.0%) | pH 없이 판정하고 **신뢰 표시를 낮춘다.** 없는 값을 채우지 않는다 | 인접 필지 참고값을 **출처를 구분해** 보조 표시 |
| **최근 7일 관측을 판정 점수에 넣지 않는다** | 화면에 보여주되 `판정 점수에 넣지 않고 상황 참고용`이라고 함께 적는다 | 관측소 거리에 따른 가중 방식을 검증한 뒤 반영 |
| **확인 기간이 3일이다** (단기예보 범위) | 선택 기간을 1일·3일로 한정해 표시 | 중기예보를 연결해 기간 확장 |
| **AI 설명 제공자가 연결되지 않았다** | 규칙으로 조립한 문장을 쓰고, LLM 출력이라고 말하지 않는다 | 어댑터 한 곳 교체 → 출력 검증 통과 시 표시 |
| **작물 5종** (감자·상추·오이·사과·배) | 선택 목록을 5종으로 고정 | 공식 기준 장부를 확보한 작물만 추가 |
| **관측소가 농지와 떨어져 있다** (예: 6.45km) | 관측소 이름과 거리를 함께 표시 | — 공간 대표성 한계로 남긴다 |

### [슬라이드] 이 서비스가 하지 않는 것 (강조 블록)

> - 발병 확률을 말하지 않습니다
> - 수확량을 예측하지 않습니다
> - 재배 성공 가능성을 말하지 않습니다
>
> **심기 전 현장 확인과 지역 농업기술센터 상담을 대체하지 않습니다.**

### [슬라이드] 마무리 한 문장

> 초보 귀농인이 **판단의 근거를 처음으로 손에 쥐는 것**이 이 서비스의 목표입니다.

### 발표용 보충 설명 (슬라이드에 넣지 않음)

- 7.0%는 실측이다. 근거는 `docs/20260725_2차PC_환경재현과_실시간검증_v1.md` 9절. 토양검정 조회 API가 필지번호만 받아 법정동 단위로 넓힐 수 없는 구조적 제약이다
- `자체 설계 계수·임계값`(민감도 1.00·1.15·1.30, 강수확률 60%, 습도 85%)은 공식 기준이 아니다. 이것도 한계로 물으면 인정한다
- 필지 경계 폴리곤 표시는 좌표 변환과 렌더가 함께 필요해 본선 항목으로 미뤘다. 근거는 `docs/20260725_화면_보강_후보_메모.md`
- 토양검정 기준시각이 오래된 필지는 화면에서 `심기 전 간이 검정으로 다시 확인` 문구를 자동으로 붙인다. 36개월은 이 서비스의 운영 기준이며 공식 재검정 주기가 아니다

## 세 장 공통 — 작성 시 주의

1. **양식 표지에 남은 다른 공모전 문구를 지운다.** 양식 2장 하단에 `2026 관광데이터 활용 공모전 - 생성형 AI 활용 관광 프롬프톤`이 들어 있다
2. **개인정보·API Key·password·token을 넣지 않는다.** 양식 5장이 명시한 조건이다
3. **소개서·화면·영상의 AI 역할 설명을 일치시킨다.** 5장에서 `AI는 설명만 한다`고 썼으면 영상에서도 그렇게 말해야 한다
4. `최근 추이를 반영해 판정한다`고 쓰지 않는다. 구현과 어긋난다
5. 표가 많으므로 세 장 모두 **표 하나 + 강조 블록 하나** 구성을 넘지 않게 줄인다. 슬라이드는 문서가 아니다
