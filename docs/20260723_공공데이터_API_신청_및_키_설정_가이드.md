> 추가 API 검토: 2026-07-24  
> 상태: 최초 P0 4종과 추가 P0 3종 승인·키 입력·실호출 완료

## 1. 오늘 신청할 P0 API

예선 MVP의 최소 데이터 흐름은 `지도 좌표 → 팜맵 필지·PNU → 토양 → 단기예보 → 적합도·선택 기간 위험도`다. Antigravity Mock 검토 결과, 좌표 기반 토양검정을 직접 제공하는 최신 공식 서비스를 추가로 확인했다. 다음 세 개를 주 경로로 사용하고, 토양검정 V2는 결측·교차검증용으로 함께 신청하되 기본 화면에는 한 토양 경로만 연결한다.

| 우선순위 | API와 활용신청 링크 | MVP 역할 | 주요 입력 | 필요한 출력 | 현재 상태 |
|---|---|---|---|---|---|
| P0-1 | [농림수산식품교육문화정보원_팜 맵 조회 서비스](https://www.data.go.kr/data/15057368/openapi.do) | 지도 좌표를 실제 농지 필지와 PNU로 연결 | 변환된 X·Y 좌표, 반경 | 팜맵 ID, PNU, 지번, 법정동, 논·밭 판독 | [x] 승인·키 입력 완료 |
| P0-2 | [기상청_단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do) | 선택 기간의 기온·강수·하늘 상태 등 위험 계산 | 발표일·시각, 기상 격자 `nx`, `ny` | 예보일시, 기온, 강수확률·강수량, 습도 등 | [x] 승인·키 입력 완료 |

P0-3 공식 응답 명세에서 전기전도도 필드는 `ecd`로 확인됐다. 명세 표에는 단위가 없지만 같은 농촌진흥청 흙토람 비료사용처방 화면에서 전기전도도를 `dS/m`로 명시하므로 화면 표시·해석 단위는 `dS/m`로 확정했다. 이는 공식 서비스 간 교차근거이며 API 명세의 직접 단위 표기는 아니다. 작물·작형별 판정 기준이 확정되기 전까지 점수에는 반영하지 않는다.

### 신청 동기

- **팜맵:** 사용자가 지정한 점을 단순 행정구역이 아니라 실제 농지 필지에 연결한다.
- **단기예보:** 장기 적합도와 분리된 `선택 기간 재배 위험도`를 만든다.
- **팜맵기반 토양검정:** 지도 좌표에서 필지·토양 근거를 한 흐름으로 얻어 MVP 연결 부담을 줄인다.
- **토양검정 V2:** 주 경로가 결측일 때 PNU 기반으로 한 번 더 확인한다.

팜맵은 웹 지도의 위·경도를 API가 요구하는 좌표계로 변환해야 한다. 기상청 단기예보도 위·경도를 기상 격자 `nx`, `ny`로 변환해야 한다. 이 변환은 발급 후 기술문서와 실제 응답으로 확인한다.

주소 검색용 지도 API와 LLM API는 이 목록과 별개다. 3D 데스크톱 API는 웹 Next.js MVP의 분석 근거가 아니라 C/S 시각화 플랫폼이므로 예선 P0에서 제외한다. ASOS 시간자료·농업기상 상세 관측·AWS를 한꺼번에 붙이지 않고, 먼저 농업기상 기본 관측의 결측·공간 대표성을 확인한 뒤 필요한 한 소스만 추가한다. 외부 예측 모델 API는 현재 대상 5개 작물·노지 후보지 탐색·판정 근거가 함께 맞는 서비스가 확인되지 않았으므로 P0에서 사용하지 않는다.

농업기상 기본 관측데이터 V3와 관측지점 상세정보를 한 쌍으로 연결했다. 평창 대관령 대표 좌표에서 최근접 지점은 `강릉 안반덕이`, 직선거리 `6.45km`, 관측소 고도 `1,099m`로 확인됐다. 최근 7일 관측 7건도 정상 반환됐다. 가장 가깝다는 이유만으로 농지의 미기후를 대표한다고 단정하지 않으며, 현재 거리 구간은 화면의 참고 표식에만 사용하고 적합·위험 점수에는 가산하지 않는다.

토양특성 V3는 대표 PNU에서 1건을 반환했다. 배수·유효토심·표토토성·주토지이용·밭 적성등급 등의 원코드는 화면에 표시하지만, 공식 코드표와 의미를 대조하기 전에는 사람이 해석한 라벨이나 점수 입력으로 바꾸지 않는다. 상세 실응답은 `20260724_추가_공공데이터_실호출_감사.md`에 기록한다.

## 3. 신청·발급 절차

1. 추가 신청이 확정되면 남궁도현이 공공데이터포털 계정으로 2절의 P0 세 서비스에 각각 `활용신청`을 누른다. 1절의 최초 P0 서비스는 이미 승인·키 입력이 끝났다.
2. 신청 목적에는 해커톤 프로토타입에서 농지 위치·토양·단기 기상 기반 재배 의사결정 정보를 제공한다고 적는다.
3. 승인 여부와 신청일만 이 문서의 상태 칸에 기록한다. 인증키 값은 기록하지 않는다.
4. 공공데이터포털 마이페이지에서 일반 인증키의 Encoding/Decoding 표기를 확인한다.
5. 구현에서는 Decoding 키를 로컬 환경변수에 저장하고 HTTP 클라이언트가 쿼리 문자열을 인코딩하게 하는 방식을 우선한다.
6. 실제 호출 전 각 API 기술문서의 요청 주소, 필수 파라미터, 좌표계, 응답 형식을 다시 확인한다.

### Antigravity Mock에서 바로잡아야 할 API 정보

- 소스의 `15034381`은 현재 좌표 기반 팜맵 토양검정 OpenAPI 식별자가 아니다. 현재 공식 활용신청 페이지는 **`15058655`**다.
- 현재 공식 좌표 기반 토양검정 요청 주소는 `/rest/farmmap/getFarmmapSoilAnalysisService/getCoordinateBasedSoilAnalsInfo`다.
- 공식 요청 파라미터는 WGS84의 `x`, `y`가 아니라 `positionX`, `positionY`다. 샘플값도 투영좌표 형태이므로 좌표계는 활용가이드와 실호출로 확정해야 한다.
- Mock 소스의 예전 엔드포인트와 `WGS84 직접 입력` 가정은 실호출 코드에 그대로 사용하지 않는다.
- `--apiKey`, `--farmmapKey`처럼 키를 명령행 인자로 넘기면 PowerShell 기록과 프로세스 목록에 남을 수 있으므로 사용하지 않는다. 로컬 환경변수만 사용한다.

## 4. 실제 키 입력 위치

키 입력용 템플릿은 `config/api.env.example`이다. **이 example 파일에는 실제 키를 입력하지 않는다.**

Antigravity 소스는 참고 원본으로 보존하고, 실제 제출용 구현은 `prototype/codex-mvp`로 확정했다. 현재 Codex MVP는 앱 루트의 `.env.local`을 서버에서만 읽는다. 공유용 템플릿은 `config/api.env.example`에 유지한다.

현재 사용 위치:

```text
D:\Projects\해커톤\prototype\codex-mvp\.env.local
```

예상 변수:

```dotenv
PUBLIC_DATA_MODE=mock
DATA_GO_KR_SERVICE_KEY=
```

- 발급 전에는 `PUBLIC_DATA_MODE=mock`을 사용한다.
- 실제 응답 연결 시에만 `PUBLIC_DATA_MODE=live`로 바꾼다.
- 공공데이터포털 API들이 동일한 일반 인증키로 동작하는지 마이페이지와 실호출로 확인한다. 서비스별 키가 실제로 다를 때만 변수를 분리한다.
- `.env.local`은 향후 GitHub 공개·압축 전달·화면 공유 대상에서 반드시 제외한다.
- Codex MVP는 `DATA_GO_KR_SERVICE_KEY` 하나를 Next.js 서버 route에서만 읽는다. Antigravity 원본에는 실제 키를 중복 저장하지 않는다.

## 5. 브라우저 노출 방지

공공데이터 인증키를 `VITE_`, `NEXT_PUBLIC_` 등 브라우저 공개용 접두사가 붙은 변수에 넣지 않는다. Antigravity 프로토타입이 프론트엔드 전용이라면 다음 중 하나로 변경해야 한다.

1. Next.js API route, 서버 함수 또는 별도 경량 백엔드에서 공공데이터 API를 호출한다.
2. 프론트엔드는 우리 서버의 `/api/farm`, `/api/weather`, `/api/soil`만 호출한다.
3. 서버가 필요한 필드만 정규화해 반환하고 원본 인증키는 반환하지 않는다.

Mock 데이터도 실제 API와 같은 응답 계약을 사용하면, 화면을 다시 만들지 않고 서버 adapter만 교체할 수 있다.

## 6. 키 안전 점검

- [x] 키 값이 감사 로그·Markdown·소스코드에 출력되지 않았다.
- [x] `.env.local`이 `.gitignore`의 `.env*` 규칙으로 공개 대상에서 제외됐다.
- [ ] 브라우저 개발자도구의 Network 탭에서 공공데이터 키가 보이지 않는다.
- [x] 감사 스크립트와 앱 오류 메시지가 전체 요청 URL을 출력하지 않는다.
- [x] Mock·live·소스별 fallback 상태가 화면에서 구분된다.
- [x] API별 출처와 데이터 기준시각을 결과 화면에 표시한다.

## 7. Antigravity Mock 인수 시 확인할 내용

프로토타입은 새로 버리지 않고 우선 참고한다. 다음 순서로 판단한다.

1. 실행 방법과 프레임워크 확인
2. 화면 흐름이 합의된 `위치·작물·기간 → 분석 → 적합도·위험 → 행동`과 맞는지 확인
3. Mock 데이터 구조와 P0 API 응답을 매핑할 수 있는지 확인
4. 지도 방식과 API Key 노출 여부 확인
5. 재사용 가능한 화면·컴포넌트와 다시 만들어야 할 데이터 로직 구분
6. 원본을 보존하고 복사본에서 수정

검토 결과는 `그대로 재사용`, `화면만 재사용`, `아이디어만 참고`, `재구현` 네 가지로 나눠 기록한다.
