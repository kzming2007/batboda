## 1. 결론

**실시간 연결 4/4를 달성했다.** 대체(검증 스냅샷·시연 자료) 없이 네 소스 전부 `connected`로 응답했다. 인수·인계 문서 2-1절의 7단계 중 1~6단계를 통과했으므로, 7단계(실패 시 대응 결정)는 발동하지 않는다.

## 5. 출처 표 구현 (인수·인계 4절 4항)

`자세한 근거` 안 `계산 근거` 다음에 `사용한 자료 — 어떤 API의 어떤 값을 썼는지` 표를 넣었다. 열은 `자료 / 제공기관 / 실제 사용한 값 / 상태·기준시각`이다.

설계 결정:

- **4행으로 넣었다.** 인수·인계 초안은 토양검정과 토양특성을 나눠 5행이었지만, 화면의 `실시간 연결 4/4`와 개수가 어긋난다. 토양은 한 행으로 두고 행 안에 두 API의 필드를 함께 적었다. 관측지점 상세정보는 관측소 매핑용 보조 호출이므로 여전히 세지 않는다.
- **`실제 사용한 값`은 고정 문구가 아니라 응답에서 동적으로 채운다.** `AnalysisSource`에 `provider`·`usedFields`·`observedAtLabel`을 추가하고 엔진에서 실제 입력으로 만든다. 반경 후보 수, 확정 PNU, 지번, 예보 일수, 최근접 관측소 이름·거리가 그대로 들어간다. 표가 코드와 따로 늙지 않게 하려는 의도다.
- **코드가 아니라 공식 라벨을 쓴다.** 밭 적성등급·저해요인은 `soilCodes`의 공식 코드표로 변환한다. 원시 코드 `04`가 아니라 `4급지`, 저해요인 `경사`로 나온다.
- **과장을 피했다.** 유기물·EC는 화면 표시용이고 점수에 반영하지 않으므로 그 사실을 행 안에 적었다.
- 기존 `판단 근거` 긴 문단(`basisNote`)은 없애지 않고 `계산 근거` 하단으로 옮겼다. 산식 근거 설명이라 출처 표와 성격이 다르다.
- 최하단 상시 노출 띠는 짧은 한 줄로 바꿨다. 다만 이 띠의 서체는 8~9px로 남아 있어 영상·캡처에서 읽기 어렵다. 별건으로 조정이 필요하다.

## 6. 토양·기온 근거 누락 감사 (2026-07-25, 실시간)

팀 요청으로 토양·기온 근거가 실제로 다 불러와지는지 두 경로를 비교 호출했다. **결론: 필지를 확정하면 누락이 없다. 확정하지 않으면 토양 물리 항목 5개가 통째로 빠진다.** 그런데 두 경우 모두 화면 상단은 `실시간 연결 4/4`로 표시된다.

원인은 `lib/analysis/service.ts`의 `soilForParcel`이다. 필지가 `matched`이고 PNU가 19자리일 때만 `fetchSoilByParcel`(농촌진흥청 토양검정 V2 + 토양특성 V3)을 타고, 아니면 `fetchSoil`(농림축산식품부 농경지 토양분석)로 간다. 후자는 `physicalProfile`을 아예 채우지 않는다. 둘 다 정상 응답이라 `status`는 `connected`이므로 4/4가 된다. 실패한 게 아니라 **다른 API를 탄 것**이다.

|---|---|---|

기온 근거는 **두 경로 모두 누락이 없다.**

- 단기예보 3일: 최저·최고기온, 강수확률, 강수량, 강수형태, 습도, 풍속, 하늘 상태 전부 값이 있다. `null` 없음. 발표 2026-07-25 17:00 KST
- 농업기상 관측: 강릉 안반덕이(6.45km, 표고 1099m), 2026-07-18~07-24 7일치, 누적강수 139mm, 강수일 6일, 최저 14.6℃, 최고 26.4℃, 평균습도 94.7%, 대표성 `nearby`. `null` 없음

주의할 점 두 가지.

1. **B에서 EC가 0으로, 시료 유형이 `시설`로 온다.** 밭을 물었는데 시설(하우스) 시료가 섞인 것이다. 좌표 경로는 필지 단위 정합이 보장되지 않는다는 뜻이므로, 시연·영상에서는 반드시 필지를 확정한 뒤 분석해야 한다.
2. **`실시간 연결 4/4`는 "네 소스가 응답했다"는 뜻이고 "필드가 다 찼다"는 뜻이 아니다.** 화면은 `자료 없음` 표시와 신뢰표시 74로 이 사실을 드러내지만, 배지만 보면 오해할 수 있다. 영상에서 4/4를 근거로 말할 때 이 구분을 지킨다.

### 감사에서 발견한 출처 표 자체의 오류와 수정

첫 구현은 `실제 사용한 값`을 고정 문구로 넣어서, B 경로에서 없는 값을 있다고 적었다. 다음을 고쳤다.

- `제공기관`을 손으로 적지 않고 응답 출처 문자열에서 읽는다. B에서 `농촌진흥청`으로 잘못 표기되던 것을 `농림축산식품부`로 바로잡았다. 시연·스냅샷 출처명에는 기관명이 없으므로 그 자료가 재현하는 기관을 기본값으로 넘긴다.
- `physicalProfile`이 없으면 물리 항목을 나열하지 않고 `토양특성 V3 물리 항목 없음 — 밭 적성등급·저해요인·배수·유효토심·표토 토성 미조회`와 `필지를 확정하면 물리 항목까지 조회됩니다`를 대신 넣는다.
- 필지가 `matched`가 아니면 `반경 후보 N건에서 필지 확정`·`PNU`를 적지 않고 `필지 미확정 — 좌표 기준으로 조회했습니다`로 바꾼다. 이전에는 `PNU 농지 미확정`처럼 자기모순이었다.
- 유기물·EC를 이름만 적지 않고 실제 값과 단위를 넣는다. 시료 유형도 추가했다. B의 `시료 시설`이 화면에서 바로 보인다.
- 배수·유효토심·표토 토성도 공식 코드표 라벨로 변환해 값까지 적는다.

### 최하단 출처 띠 삭제

팀 요청으로 판정서 맨 아래 상시 노출 띠(`source-strip`)를 삭제했다. 자세한 근거의 출처 표와 내용이 겹치고, 8~9px로 읽히지 않았다. JSX와 CSS(반응형 규칙 포함) 모두 제거했고 `.source-state` 점 표시는 새 표에서 계속 쓴다. 판정서의 마지막 블록은 이제 `자세한 근거` 접기다.

검증: `tsc --noEmit` 무오류, Vitest 41/41, ESLint 무경고, production build 통과, 브라우저 DOM에서 띠 제거·제공기관 4행 정상 확인.

## 7. 핵심 로직 대조 (기준 문서 42행)

문제정의서가 요구한 핵심 로직은 `변수별 가중치, 범위 이탈 정도, 작물별 민감도, 최근 추이·단중기 예보, 결측·이상치 처리`다. 구현과 하나씩 대조했다.

| 공식 요구 | 구현 위치 | 상태 |
|---|---|---|
| 변수별 가중치 | `scoreExplanations` 3종(적합·위험·근거상태), 항목마다 formula와 term | 충족 |
| 범위 이탈 정도 | pH 이탈 거리 × 민감도, 기온 적온 이탈 | 충족 |
| 작물별 민감도 | `sensitivityMultipliers` 3단계 | 충족 |
| 결측·이상치 처리 | `evidenceGapPenalty`, `outlierPenalty`, 허용범위 밖 값 제외 | 충족 |
| 최근 추이 | `recentClimate` | **점수 미반영** |
| 단중기 예보 | 단기예보 3일만 | **중기 미연결** |
| 규칙 + LLM 자연어 리포트 | `lib/report` 계약 | **제공자 미연결** |

어긋난 세 가지의 성격이 다르다.

1. **최근 추이가 판정에 안 들어간다.** `recentClimate`는 신뢰표시(`missingCount`)와 화면 표시에만 쓰이고, 적합도·위험 점수는 `input.weather.days`(단기예보)만 사용한다. 화면에는 최근 7일 누적강수 139mm·강수일 6일이 나오지만 판정 숫자에는 기여하지 않는다. 문서·영상에서 `최근 추이를 반영한다`고 말하면 사실과 어긋난다. 지금 표현은 `최근 관측을 함께 보여준다` 수준으로 유지해야 한다.
2. **중기예보 미연결** — 2026-07-25 팀 결정 6번으로 화면에서 제외했다. 활용신청이 선행되어야 하므로 예선 안에서는 되돌리지 않는다.
3. **LLM 제공자 미연결** — 2026-07-25 팀 결정 2번. 계약·검증·대체 경로는 구현돼 있다.

2·3은 이미 팀이 알고 내린 결정이고, 1은 오늘 대조에서 새로 확인한 항목이다. 1은 코드를 고치는 대신 표현을 맞추는 쪽이 마감까지 안전하다.

미해결로 남은 계측 문제도 그대로다. 감점 폭 ±20%에서 주판정 단계는 0% 변동이지만 위험 등급은 lenient 60% 변동한다(인수·인계 5절).

## 8. 토양특성 V3 유실 버그와 수정 (2026-07-25, 중요)

팀이 `대관령면 294-39`에서 `토양 적성 자료 없음`을 발견해 확인한 결과, **공공데이터 문제가 아니라 우리 코드 버그였다.** 밭 적성등급은 이 서비스의 주 판정 근거이므로 영향이 컸다.

### 증상

필지를 확정했는데도(PNU 표시됨) 토양 출처가 `농림축산식품부 농경지 토양분석`으로 후퇴하고 밭 적성등급이 `자료 없음`이 됐다. 화면에는 `필지번호로 토양을 조회하지 못해 좌표로 다시 확인합니다. (공공데이터 응답 오류: 요청 데이터 없음)` 경고가 떴다.

### 원인

공공 API에 직접 물어 확인했다. 세 필지 모두 **토양특성 V3는 정상 응답(item 1건)** 이었고, 없는 것은 토양검정 V2뿐이었다.

| PNU | 토양특성 V3 | 토양검정 V2 |
|---|---|---|
| 279-15 | 200 정상 · 1건 | 200 정상 · 1건 |
| 294-39 | 200 정상 · 1건 | 301 요청 데이터 없음 |
| 267 | 200 정상 · 1건 | 301 요청 데이터 없음 |

`lib/public-data/client.ts`의 `apiItems`는 결과코드가 정상이 아니면 `throw`한다. 그런데 `fetchSoilByParcel`이 이 함수를 `Promise.allSettled` **바깥의 동기 코드**에서 호출했다.

```
const chemical = chemicalResult.status === "fulfilled" ? apiItems(chemicalResult.value)[0] : undefined;
```

`request()`는 HTTP 200이면 결과코드와 무관하게 성공으로 돌아온다. 따라서 V2가 301이어도 `status === "fulfilled"`가 되고, 이어지는 `apiItems`가 throw하면서 **함수 전체가 중단됐다.** 바로 아래의 `if (!chemical && !physical)` 가드가 이 경우를 위해 있었지만 도달할 수 없었다. 결과적으로 **정상 응답한 토양특성 V3까지 함께 버려졌다.**

### 수정

항목 추출을 소스별로 감싸는 `settledItems`를 추가해, 한쪽이 `요청 데이터 없음`이어도 다른 쪽 값을 살린다. `fetchSoil`(좌표 경로)은 이미 `try` 안에 있어 영향이 없었다.

### 효과

같은 반경 1km 후보에서 무작위 표본 24건을 재측정했다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 토양특성 V3 확보 | **0 / 24** | **24 / 24** |

문제로 지목된 294-39는 `3급지 · 저해요인 경사 · 배수 양호 · 유효토심 깊음 · 표토 식양토`로 정상 표시된다. 표본에서 2~4급지가 고르게 나오므로 대관령 일대 시연 필지 선택지가 넓어졌다.

화학성이 없는 필지는 출처가 `농촌진흥청 토양특성 V3`로 표시되고, pH·유기물·EC는 `토양검정 화학성 자료 없음 — pH·유기물·EC 미조회`로 적는다. 신뢰표시는 100 대신 84가 되어 결측이 점수에 드러난다. 화학성이 없으면 `검정 시점` 라벨을 붙이지 않는다.

### 남는 사실

- **279-15는 여전히 유일하게 화학성까지 확보된 필지**다(표본 기준). pH를 화면에 보여주려면 279-15로 녹화해야 한다.
- 밭 적성등급만 보여도 되면 다른 필지도 쓸 수 있다.
- 이 버그는 기존 테스트 41개가 잡지 못했다. 실호출 감사로만 드러났다. 회귀 테스트 추가는 본선 과제로 남긴다.

검증: `tsc --noEmit` 무오류, Vitest 41/41, ESLint 무경고, production build 통과.

수정 파일: `lib/public-data/client.ts`, `lib/analysis/engine.ts`

### 수정 후 독립 재측정 (같은 날, 별도 표본)

수정이 실제로 유지되는지 표본을 바꿔 다시 쟀다. 반경 1km 후보 356건 / 고유 PNU 258건에서 무작위 12건(seed 11).

| 필지 | 밭 적성등급 | pH | 신뢰표시 |
|---|---|---|---|
| 211-2전 | 4급지 | 없음 | 84 |
| 201-25전 | 2급지 | 없음 | 84 |
| 산79-8임 | 4급지 | 없음 | 84 |
| 201-31전 | 2급지 | 없음 | 84 |

**밭 적성등급 12/12 확보, pH 0/12.** 1~4급지가 고르게 나오므로 등급 분포도 정상이다. 294-39는 6회 반복 호출에서 모두 `3급지 / pH 없음`으로 동일했고, 279-15는 3회 반복에서 모두 `화학성 V2 + 토양특성 V3 / pH 7 / 4급지 / 신뢰 100`이었다. 두 경로 모두 재현성이 있다.

즉 `pH 없음`은 남은 버그가 아니라 **토양검정 화학성 V2의 커버리지 한계**다. 이 API는 농민이 실제로 시료를 제출해 검정받은 이력만 담고 있고, 토양특성 V3(토양도)는 전국을 덮는다.

### 검토했으나 채택하지 않은 보완책

pH가 빈 필지를 좌표 기반 `농림축산식품부 농경지 토양분석`의 화학성으로 채우는 방법을 검토했으나 **채택하지 않는다.** 6절 감사에서 그 API가 같은 좌표에 `시료 유형 시설(하우스)`, `EC 0`을 반환하는 것을 확인했다. 밭 판정에 시설 시료를 섞으면 필지 단위 조회라는 전제가 깨진다. 빈 값을 그대로 두는 편이 정확하다.

### 심사에서 다루는 방식

심사위원이 임의 필지를 찍으면 pH가 빈 화면을 보게 된다. 숨기지 않는다.

- 주판정(재배 판단 단계)의 근거는 **밭 적성등급**이고 이 자료는 커버리지가 넓다. pH가 없어도 주판정은 나온다.
- pH가 없으면 신뢰표시가 84로 내려가고 해당 항목은 `자료 없음`으로 적는다. 추정해서 채우지 않는다.
- 이 동작 자체가 운영 가능성 항목의 근거다. `검정 이력이 없는 필지는 없다고 말한다`가 설계다.

## 9. 주의

`.env.local`은 로컬 전용이다. 문서·채팅·화면 캡처에 키 값을 노출하지 않는다. 저장소에 남아 있는 `env.local` 템플릿에 키가 평문으로 들어 있으므로, 배포·공유 대상에서 제외하는지 확인이 필요하다.
