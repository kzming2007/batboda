# 검증 캐시와 설명 리포트 계약 구현

> 작성일: 2026-07-25
> 구현 위치: `prototype/codex-mvp`
> 검증: Vitest 41개 통과, ESLint 통과, Next.js production build 통과
> 관련 결정: 2026-07-25 팀 결정 — 영상 안정성을 위한 검증 캐시 도입, LLM은 계약만 구현하고 제공자 연결은 보류

## 1. 검증 캐시

### 대체 순서

`실시간 호출 → 검증 스냅샷 → 시연 자료(Mock)` 순서로 소스별로 독립 대체한다. 한 소스가 실패해도 성공한 실데이터는 유지한다.

| 상태값 | 화면 표시 | 의미 |
|---|---|---|
| `connected` | 공공데이터 연결 | 실시간 응답 |
| `cache` | 검증 스냅샷 | 실제 응답에서 확인된 값을 저장해 둔 것 |
| `fallback` | 대체 자료 | 검증 스냅샷이 없어 시연 자료로 대체 |
| `mock` | 시연용 검증 자료 | 처음부터 시연 모드로 실행 |

### 구성

- `lib/cache/snapshots/verified.json` — 스냅샷 값과 출처 정보
- `lib/cache/verifiedSnapshot.ts` — 좌표 대조(±0.02°)와 도메인 타입 변환
- `lib/analysis/service.ts` — 소스별 대체에서 캐시를 먼저 시도
- `app/api/cache/capture/route.ts` — 개발 환경 전용 수집 경로

### 출처와 재현 절차

현재 시드 스냅샷은 `collectedBy: documented-audit`이다. 값은 `docs/20260724_추가_공공데이터_실호출_감사.md`와 `docs/20260723_공공데이터_실응답_파이프라인_감사.md`에 기록된 실호출 확인값(PNU `5176038024102790015`, 팜맵 ID `427603802400956`, pH `7.0`, 유기물 `18 g/kg`, 시료 `시설`, 밭 4급지·경사, 최근접 `강릉 안반덕이` `6.45km`, 최근 7일 강수 `139.0mm`)이며 사람이 새로 만든 값이 아니다. 단기예보는 일자별 실응답 기록이 없어 시드에 넣지 않았고 `weather: null`이다.

실응답을 직접 저장하려면 개발 서버에서 다음을 호출한다. 응답을 그대로 `verified.json`에 쓰고 수집시각을 KST로 기록하며, 이때 `collectedBy`는 `capture-route`가 된다.

```text
/api/cache/capture?lat=37.675&lng=128.718&parcelId=5176038024102790015&horizonDays=3
```

이 경로는 `NODE_ENV=production`에서 403을 반환하고, 요청한 PNU가 팜맵 후보에 없으면 409로 거부한다. 즉 좌표와 필지가 정합될 때만 스냅샷이 저장된다.

### 화면 표시

- 소스별 상태 점에 `cache` 색을 추가했다.
- 캐시를 쓴 경우 결과 화면에 `검증 스냅샷 사용` 안내를 띄우고 어떤 소스가 대체됐는지, 언제 수집한 값인지, 출처 문서가 무엇인지 문장으로 표시한다.
- 데이터 근거 표식은 `실시간 연결 N/4 · 검증 스냅샷 N건` 형식으로 실시간과 캐시를 분리해 센다. 캐시는 실시간 연결로 세지 않으므로 근거 점수가 실시간보다 낮게 나온다.

### 남은 판단

- 단기예보 스냅샷은 녹화 직전 `capture` 경로로 한 번 저장할지, 예보만 실시간으로 둘지 팀이 정한다.
- 캐시는 `평창 대관령` 좌표 반경에만 적용된다. 다른 대표 지역을 추가하려면 스냅샷 파일 구조를 지역별 배열로 확장해야 한다.

## 2. 설명 리포트 계약

LLM 제공자는 연결하지 않았다. 대신 계약·검증·대체 경로를 먼저 구현했고, 화면은 현재 규칙 기반 설명을 보여준다.

### 구성

| 파일 | 역할 |
|---|---|
| `lib/report/bundle.ts` | 근거 묶음 생성. 규칙 엔진이 확정한 판정·근거·행동·한계와 사용 가능한 숫자 목록만 담는다 |
| `lib/report/contract.ts` | 시스템·사용자 프롬프트, 금지 표현, 출력 검증 |
| `lib/report/provider.ts` | 제공자 자리. 미등록이면 이유와 함께 `null` |
| `lib/report/index.ts` | 생성·검증·대체 흐름과 단계 기록 |

### 검증 항목

1. 판정 단계를 그대로 인용했는지
2. 금지 표현이 없는지 — `성공 확률`, `발병 확률`, `보장`, `처방`, `진단`, `AI가 판단`, `추천 품종` 등. `강수확률`처럼 공식 데이터 항목 이름은 허용한다
3. 근거 묶음에 없는 숫자를 만들지 않았는지
4. `결론 / 근거 / 먼저 할 일 / 주의` 네 부분이 있는지
5. 길이가 범위 안인지

검증에 실패하거나 호출이 실패하면 같은 근거의 규칙 기반 문장으로 대체하고, 화면에는 `규칙 기반 설명(검증 실패 대체)`처럼 이유가 드러나는 라벨을 표시한다.

### 화면에 드러나는 생성 과정

결과 화면의 `쉬운 설명` 아래에 5단계를 그대로 보여준다.

| 단계 | 현재 상태 |
|---|---|
| 근거 묶음 만들기 | 수행 |
| 설명 규칙 적용 | 수행 |
| 설명 생성 | 건너뜀 — 제공자 미정 |
| 출력 검증 | 건너뜀 — 검증할 초안 없음 |
| 화면 전달 | 수행 — 규칙 기반 설명 |

제공자를 등록하면 3·4단계가 `수행`으로 바뀌고 나머지 구조는 그대로다. 규칙 기반 설명 자체도 같은 검증 규칙을 통과하는지 테스트로 확인한다.

### 제공자 연결 방법

`registerReportProvider({ name, generate })` 하나만 등록하면 된다. 키는 서버 환경변수로만 읽고, 프롬프트에는 근거 묶음 외의 정보를 넣지 않는다. 제공자·비용·키는 아직 팀 결정 대기 항목이다.

## 3. 화면 문구 정리

`docs/20260725_결과화면_문구_감사_v1.md`의 P0·P1 항목을 적용했다. 주요 변경은 다음과 같다.

- 영어 장식 라벨 제거: `FIELD DECISION WORKSPACE`, `MODEL STATUS`, `CALCULATION LEDGER`, `RULE INDEX`, `GROUND`, `WINDOW`, `NEXT ACTION`, `SOIL MAP V3`, `RECENT OBSERVATION`
- 내부 용어 제거: `Mock`, `P0`, `정합`, `대시보드`, `근거 충족도`
- 공식 용어 병기: `PNU(필지 고유번호)`, `팜맵 ID(농지 도형 번호)`, `유효토심(뿌리 깊이)`, `표토 토성(겉흙 종류)`
- 숫자 카드 이름을 `토양 조건 점수(보조)`, `가까운 N일 위험 점수(보조)`로 바꿔 단계 판정이 주결론임을 드러냄

미적용 항목은 감사 문서 6절의 두 가지다. 요구사항 충족 블록은 상태값 어휘만 바꿨고 위치는 그대로이며, 숫자 카드의 시각적 비중 조정은 팀 확인 후 진행한다.

## 4. 검증 명령

```powershell
cd D:\Projects\해커톤\prototype\codex-mvp
npm run test
npm run lint
npm run build
```

2026-07-25 기준 Vitest 41개(검증 캐시 5개, 설명 계약 5개 추가), ESLint, production build를 통과했다. 시연 모드 화면은 브라우저에서 렌더링과 문구를 확인했다. 실데이터 모드의 캐시 대체 경로는 실제 API 실패 상황을 아직 재현하지 않았으므로, 녹화 전에 키를 끄거나 좌표를 바꿔 한 번 확인해야 한다.
