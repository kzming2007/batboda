> 검토 방법: PowerPoint로 10장을 PNG로 내보내 전부 눈으로 봤다. `pptx`를 풀어 글자 크기·발표자 노트·이미지 배치 좌표를 읽었다. 캡처 PNG는 원본을 열어 값을 읽고 슬라이드·대본과 대조했다.

## 결론

**이대로는 발표할 수 없다. 차단 요소는 두 개다.**

1. **S10에 미완성 점선 틀과 내부 캡처 명세가 그대로 남아 있다.** 화면에 `C12 · QR`, `QR. 여백 포함.`이 관객에게 보인다. 마지막 장이라 심사위원이 질의응답 5분 동안 계속 보게 된다.
2. **슬라이드에 얹힌 캡처 21개 배치가 전부 종횡비가 틀렸다.** 가로로 최대 259% 늘어나거나 78% 눌려 있다. `build_deck.js` 51~52행이 스스로 적어 둔 원칙 — 「원본 비율을 지킨다 — 제품 화면을 늘리면 그 자체가 거짓이 된다」 — 이 코드에서 지켜지지 않았다. 가장 심한 S7의 근거 캡처는 글자가 뭉개져 증거 역할을 못 한다.

둘 다 `발표/build_deck.js`를 고쳐 다시 빌드하면 해결된다. 1번은 5분, 2번은 30~45분이다. 12:00 제출까지 시간 안에 들어간다.

내용·수치·구성은 문제가 없다. 캡처에 적힌 값과 슬라이드·대본의 값이 어긋난 곳은 없었다(6.5km / 6.45km 한 건은 반올림, 아래 「고치지 말 것」). 발표자 노트 10장에 초·대사·금지 목록이 모두 들어 있고 초 합계 282초가 대본과 일치한다. 관객이 보면 안 되는 진행 지시문이나 `[사실]`·`[제안]` 같은 내부 표기는 S10 하나를 빼면 없다.

**수정안** — `captureFrame` 61행을 교체한다. 틀 안에 원본 비율로 넣고 가운데 정렬한다.

```js
function pngSize(f) {
  const b = fsx.readFileSync(f);
  return { w: b.readUInt32BE(16), h: b.readUInt32BE(20) }; // PNG IHDR
}

// 61행 대체
const n = pngSize(file);
const k = Math.min(w / n.w, h / n.h);
const dw = n.w * k, dh = n.h * k;
s.addImage({ path: file, x: x + (w - dw) / 2, y: y + (h - dh) / 2, w: dw, h: dh });
```

**적용 순서**

1. 위 패치 → 재빌드 → PNG로 다시 내보내 10장을 눈으로 확인한다. 여기까지가 필수다.
2. 확인하면 빈 여백이 생기는 자리가 나온다. 시간이 남으면 그 자리만 손댄다.
   - **S5**: 틀 폭 5.88in에 3.42in 이미지가 들어가 좌우에 여백이 남는다. 틀 폭을 3.42in로 줄여 두 카드를 붙이면 「같은 농지」가 더 잘 읽힌다.
   - **S7**: C04b는 세로형(비율 0.73)이고 틀은 가로형(2.62)이다. 비율을 지키면 폭 2.03in로 작아진다. **지금의 뭉개진 상태보다는 낫다.** 시간이 있으면 틀을 세로형으로 바꾸고 HTTP 401 상자를 좌측 카드 아래로 옮긴다.
   - **S8·S9(C10)**: 원본이 가로로 매우 긴 띠라 비율을 지키면 얇은 띠가 된다. 정상이다. 틀 높이를 줄여 여백만 없애면 된다.
3. **시간이 부족하면 1번만 하고 멈춘다.** 여백이 남은 슬라이드는 어색하지만, 늘린 제품 화면은 제품을 잘못 보여주는 것이다. 코드 주석이 스스로 그렇게 적어 두었다.

### 3. S7 — 슬라이드의 주장과 옆에 붙은 근거가 맞지 않는다

**파일** `발표/20260805_밭보다_본선발표_v2.pptx` S7 · 근거 `발표/캡처/20260805_C04b_상태_기준시각.png`

제목은 「세 가지 상태를 화면에서 구분합니다」이고 좌측에 실시간 / 검증 스냅샷 / 시연용 자료 세 칸이 있다. 그런데 우측 C04b에는 **네 소스가 모두 `● 실시간` 하나뿐이다.** 「구분한다」의 증거가 화면에 없다. 하단 HTTP 401 상자도 문장 진술이고 캡처가 없다(내용설계가 조작 캡처를 금지했으므로 이건 맞는 처리다).

이 상태로 심사위원이 좌우를 비교하면 「세 가지라고 써 놓고 하나만 보여준다」로 읽힌다. 운영 25점의 핵심 장이다.

**수정안 — 말로 메운다. 슬라이드는 건드리지 않는다.** 30초 안에 이 한 문장을 넣는다.

> "지금 화면은 네 소스가 모두 실시간입니다. 실패하면 그 소스만 이 자리 표시가 바뀝니다."

대본 v4 S7의 「소스마다 따로 표시하고」 뒤에 붙이면 초가 늘지 않는다. 이 문장이 없으면 근거가 주장을 배반한다.

### 4. S2 — 우측 4칸 카드는 금지 목록 위반이고, 내용도 옆 표의 반복이다

**파일** `발표/build_deck.js` (S2 정의 부분)

내용설계 v1의 전 슬라이드 공통 금지에 「장식 도형, 아이콘 나열, **3~4칸 카드 배열**, 아키텍처 다이어그램을 쓰지 않는다. 증거는 제품 화면 조각이다」가 있다. S2 우측은 둥근 사각형 4칸(농지 경계 / 토양 특성·화학성 / 단기예보 / 최근 7일 관측)이고, **네 칸의 내용은 좌측 C04 표의 「제공기관」 열을 그대로 옮긴 것이다.** 같은 슬라이드에서 같은 정보를 두 번 준다.

여기에 두 번째 문제가 겹친다. 이 카드 안에 **`흙토람`이 적혀 있다.** 내용설계 금지 목록은 「흙토람·타 팀 이름을 슬라이드에 쓰지 않는다」다. 대본 v4 §2는 「흙토람은 우리가 쓰는 자료의 출처로만 부른다」로 허용하고 있어 두 문서가 충돌한다. 어느 쪽이든 **전략적 손해가 있다**: 대본 §5의 예상 질문 1번이 「흙토람과 무엇이 다릅니까」다. 슬라이드에 그 이름을 써 두면 심사위원에게 비교 프레임을 먼저 건네는 셈이다. 참고로 C04 표의 제공기관 열은 「농촌진흥청」까지만 적고 흙토람을 쓰지 않는다.

**수정안** — 4칸을 지우고 텍스트 두 줄로 바꾼다. C04 표를 그 폭까지 키운다.

> 네 갈래 · 기관도 단위도 기준시각도 다릅니다
> 농림축산식품부 · 농촌진흥청 · 기상청 — 네 자료의 기준시각이 2022-12-30부터 2026-08-05까지 걸쳐 있습니다

기관명은 표에 이미 있고, 기준시각 범위는 표에서 바로 확인되는 사실이라 새 주장이 아니다. 금지 위반과 중복과 흙토람 노출이 한 번에 해소된다. 10분.

**시간이 없으면 최소 조치**: 두 번째 카드의 「농촌진흥청 흙토람」을 「농촌진흥청」으로만 바꾼다. 1분.

### 5. S4 — 우측 썸네일 5개는 백업으로 쓸 수 없다. 대본 §3-3의 전제가 틀렸다

**파일** `docs/20260805_발표대본_v4.md` 178행 · `발표/20260805_밭보다_본선발표_v2.pptx` S4

| **122행** | 「근거 자리가 **전부** 점선 틀로 비어 있다. 이것이 지금 **유일한** 차단 요소다」 | 낡았다. 12건이 들어가 남은 점선 틀은 **S10 하나**다. 그리고 「유일한」은 이제 사실이 아니다 — **종횡비 왜곡이 더 큰 차단 요소다** |
| 133행 | 「캡처의 가독성은 얹은 뒤에만 알 수 있다」 | 이제 알 수 있다. S7 C04b와 S6 C08은 읽히지 않고, S4 5칸은 3~6% 배율이다 |

**§2의 두 판단은 맞다.** S3 화살표를 구조 표시로 본 것(83행), S6 각주를 이 덱에서 가장 중요한 문장으로 본 것(85행) 모두 유지한다.
